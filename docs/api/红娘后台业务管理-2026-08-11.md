# 红娘后台业务管理接口

基础地址：`/api/v1`。所有接口要求 `Authorization: Bearer {matchmaker_admin_access_token}`，请求和响应使用 `application/json`。

## 门店与资源分配

| 方法 | URL | 用途 |
|---|---|---|
| GET | `/admin/matchmaker/stores/{store_id}` | 查询门店详情 |
| PATCH | `/admin/matchmaker/stores/{store_id}` | 修改门店名称、展示名、地区和自动分配开关 |
| PATCH | `/admin/matchmaker/stores/{store_id}/status` | 修改门店状态，状态为 `1` 正常、`2` 关闭、`3` 停用 |
| GET | `/admin/matchmaker/stores/{store_id}/members?page=1&page_size=20` | 分页查询门店成员 |
| POST | `/admin/matchmaker/stores/{store_id}/members` | 添加 `store_manager` 或 `store_matchmaker` |
| DELETE | `/admin/matchmaker/store-members/{member_id}?reason=...` | 结束门店成员关系 |
| GET | `/admin/matchmaker/stores/{store_id}/report` | 查询有效成员数和资源分配数 |
| GET | `/admin/matchmaker/assignments?page=1&page_size=20&search=...` | 分页查询资源分配及历史 |
| POST | `/admin/matchmaker/assignments/{assignment_id}/end?reason=...` | 结束有效资源分配 |

分页响应统一为 `items/page/page_size/total/has_more`。

## 财务

| 方法 | URL | 用途 |
|---|---|---|
| GET | `/admin/finance/orders` | 按状态、用户、订单号分页查询订单 |
| GET | `/admin/finance/withdrawals` | 按状态分页查询提现 |
| GET | `/admin/finance/ledger` | 按账户类型和账户 ID 分页查询资金流水 |

退款、提现审核、订单结算继续使用现有接口，并复用既有状态机和幂等写入逻辑。

**敏感操作（2026-10-04 起）**：`POST /admin/finance/orders/{order_id}/refund` 与 `PATCH /admin/finance/withdrawals/{withdrawal_id}` 必须携带 `Idempotency-Key`（8–128 字符）与 `?confirm=true`：缺少幂等键返回 **422**，缺少二次确认返回 **428**，同一幂等键重复提交直接回放上次响应、不重复退款或放款。契约详见 [`docs/api/后台数据范围与敏感操作-2026-10-04.md`](后台数据范围与敏感操作-2026-10-04.md)。

## 约见

| 方法 | URL | 用途 |
|---|---|---|
| GET | `/admin/matchmaker/meetings/requests` | 分页查询约见申请 |
| GET | `/admin/matchmaker/meetings` | 分页查询约见记录 |
| GET | `/admin/matchmaker/meetings/{meeting_id}` | 查询约见详情 |
| PATCH | `/admin/matchmaker/meetings/{meeting_id}` | 修改时间、地点、状态和取消原因 |
| GET | `/admin/matchmaker/meetings/{meeting_id}/feedback` | 查询双方反馈 |

已取消的约见不能恢复；取消状态必须提供原因。

## 错误与兼容

参数错误返回 `422`，未登录返回 `401`，无权限返回 `403`，资源不存在返回 `404`，状态冲突返回 `409`，敏感操作缺二次确认返回 `428`。接口继续使用现有 `/admin` 兼容前缀，不新增 `/admini` 前缀。

**变更记录（2026-10-04）**：本模块全部接口落地后台数据范围（D-4）——约见申请按 `matchmaker_id`/`organization_id`、约会记录按 `organizer_id`/`organization_id` 套用 `ALL/SELF/STORE/ORGANIZATION` 四档；财务侧订单/日报/分成/导出按「消费会员的生效归属」收口，提现与资金流水按账户类型（会员 / 门店组织）分别锚定。越权读取按 `404` 返回，越权写操作不落库。
