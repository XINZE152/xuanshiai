# 设置页接口

## 隐私设置

#### `GET /api/v1/users/me/privacy`

**基本信息**：登录后查询当前用户隐私设置，Bearer Token，响应 `200 application/json`。无请求体。

**返回字段**：除 `user_id` 外，`profile_visibility` 为 `all/friends/only_me`，`message_privacy` 为 `all/friends/certified`；其余字段保持社交消息文档定义，`updated_at` 为最后更新时间（未更新时可为 `null`）。

**成功示例**：
```json
{"user_id":1,"profile_visibility":"all","message_privacy":"all","show_profile":true,"notify_message":true,"updated_at":null}
```

#### `PUT/PATCH /api/v1/users/me/privacy`

**基本信息**：登录后部分更新当前用户设置，Bearer Token，`Content-Type: application/json`，成功 `200`。两种方法契约相同；空对象幂等返回当前设置。

**请求参数**：

| 参数 | 位置/类型 | 必填 | 校验/枚举 | 含义 |
|---|---|---|---|---|
| `profile_visibility` | body string/null | 否 | `all`、`friends`、`only_me` | 资料可见范围 |
| `message_privacy` | body string/null | 否 | `all`、`friends`、`certified` | 接收消息权限 |
| 其他隐私字段 | body boolean/integer | 否 | 见 `docs/api/社交消息.md` | 原有设置，向后兼容 |

**请求示例**：
```http
PATCH /api/v1/users/me/privacy HTTP/1.1
Authorization: Bearer <access_token>
Content-Type: application/json
```
```json
{"profile_visibility":"friends","message_privacy":"certified"}
```
非法示例：`{"profile_visibility":"public"}`，返回 `422`。

**返回示例**：返回完整 `PrivacyResponse`，新增字段示例：
```json
{"user_id":1,"profile_visibility":"friends","message_privacy":"certified","updated_at":"2026-09-04T07:30:00"}
```

**业务规则**：`friends` 仅允许双方存在有效匹配（`user_match.status` 为 `1` 或 `2`）；`only_me` 不进入推荐且不能浏览；`certified` 仅允许发送方实名认证通过。规则与旧的 `show_profile`、`who_can_see_me`、`only_auth_can_contact` 叠加，**取更严格限制**，任一项拒绝即不可见。更新使用 upsert，可重复提交。

**实际执行范围（2026-09-29 核对）**：

| 设置 | 生效位置 | 尚未覆盖 |
| --- | --- | --- |
| `profile_visibility` | 由 `app/services/candidate_visibility.py` 统一策略执行：推荐/广场、搜索、`/users/{id}/profile` 详情与访客、收藏与浏览记录、申请收发、爆灯、附近的人、AI 搜索/推荐/匹配度/分身资料 | 社区动态流与详情、聊天会话列表、纸飞机列表与回复、直播席位 |
| `message_privacy` / `only_auth_can_contact` | `POST /chat/sessions/{session_id}/messages` 发送消息前置校验 | 结构化会话请求、纸飞机消息、AI 分身消息 |
| `show_profile` / `who_can_see_me` | 同 `candidate_visibility` 共享谓词 | 同 `profile_visibility` 的未覆盖项 |

未覆盖项按 fail-closed 处理：这些读取路径不因隐私设置而放宽，但也尚未按设置收紧；补齐前不得对外宣称这些入口已受该设置约束。`message_privacy=all` 不代表陌生人可以绕过双方同意直接发消息——聊天仍须先建立有效会话与匹配。

**错误**：`401` 未登录；`403` 消息权限不足；`422` 字段类型或枚举非法。前端应保留旧 PUT 调用，或迁移到 PATCH。

## 检查更新

#### `GET /api/v1/app/version?platform=mp-weixin&version=1.0.0`

**基本信息**：登录后查询平台最新启用版本，Bearer Token，响应 `200 application/json`，无请求体。

**请求参数**：`platform`（query string，必填，小写字母开头，2~32 字符，如 `mp-weixin`）；`version`（query string，必填，1~4 段数字版本，如 `1.0.0`，最长 32 字符）。

**成功响应**：
```json
{"platform":"mp-weixin","latest_version":"1.0.1","current_version":"1.0.0","has_update":true,"is_force_update":false,"download_url":"https://example.com/update","update_log":["修复已知问题"]}
```
无更新时 `has_update=false`、`is_force_update=false`、`download_url=null`、`update_log=[]`。

**返回字段**：`latest_version/current_version` 为版本字符串；`has_update` 是否有更新；`is_force_update` 是否强制更新（无更新时固定 false）；`download_url` 更新地址，无更新为 null；`update_log` 更新说明数组。

**业务规则**：版本按数字段比较并补齐尾部零；只读取 `app_release_version.is_active=1` 的最高版本。未配置版本的平台不返回伪造数据。

**错误**：`400` 平台或版本格式错误；`401` 未登录；`404` 暂无该平台版本信息；`503` 版本表不可用。错误示例：`{"detail":"平台或版本号格式错误"}`。

**变更记录（2026-09-04）**：新增版本检查接口；隐私接口新增字段并增加 PATCH，旧 PUT 保持兼容。版本发布记录由 `app_release_version` 表维护，部署时需录入实际版本和下载地址。
