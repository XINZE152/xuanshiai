# 安全中心接口

接口前缀：`/api/v1`。

`GET /security/center` 返回安全中心页（`pagesSub/profileExtra/security.uvue`）所需的全部数据：hero 文案、本月治理数字、反诈卡片、客服入口文案、风险提示。**需要登录**（`get_current_user`），游客不可用。

### 响应

```json
{
  "hero": { "title": "宣誓爱安全中心", "subtitle": "守护你的社交安全", "note": "隐私守护 · 行为规范 · 资料核验" },
  "governance": {
    "month_label": "11月",
    "total_processed": 12,
    "content_actions": 9,
    "dismissed": 3,
    "temporary_bans": 4,
    "permanent_bans": 2,
    "other_restrictions": 6
  },
  "fraud_articles": [
    { "type": "cheat_notice", "mark": "防", "tone": "guide-mark", "title": "先核实，再转账", "description": "冒充客服或红娘索要验证码、投资充值、借款代收，一律先向平台核实。" }
  ],
  "ai_support_title": "需要操作指引？联系客服",
  "ai_support_description": "客服只提供入口说明，不会代替你提交举报",
  "risk_notice": "遇到现实中的人身或财产风险，请停止互动、保存记录，并及时联系当地警方或紧急服务。"
}
```

`governance` 为 `null` 表示**本月确实没有任何治理动作**（不是接口失败）。前端据此显示「暂无本月治理数据」，与「加载失败」是两种不同状态。

### 治理口径

| 字段 | 数据源 | 定义 |
|---|---|---|
| `total_processed` | `user_report` | 本月已完结举报：`status IN (1 已处理, 2 驳回)` 且 `reviewed_at >= 月初` |
| `content_actions` | `user_report` | 其中 `action IN ('hide_content','restore_content')` 的内容处置数 |
| `dismissed` | `user_report` | 其中 `status = 2`（驳回）。驳回也算已处理，但单独展示，不和「处罚」混为一谈 |
| `temporary_bans` | `user_restriction` | 本月创建、`restriction_type='TOTAL_BAN'` 且 `ends_at` 非空 |
| `permanent_bans` | `user_restriction` | 本月创建、`restriction_type='TOTAL_BAN'` 且 `ends_at` 为空 |
| `other_restrictions` | `user_restriction` | 本月创建、非 `TOTAL_BAN` 的功能限制（POST/COMMENT/MESSAGE/APPLICATION_RESTRICTED） |

- 统计窗口是自然月，`month_start` 按 UTC 计算，与库里 `reviewed_at` / `created_at` 由 `UTC_TIMESTAMP()` 写入的 naive UTC 对齐。
- 统计的是「本月**做过**多少处置」，因此已解除（`status=2`）的限制仍计入当月数字。
- **不返回 `warnings`**：`user_restriction.restriction_type` 只有 `TOTAL_BAN` 与四类功能限制，系统没有「警告」这种处置类型。原设计稿的「警告」一栏由 `other_restrictions`（功能限制）表达，不编数字。

### 缓存

按月份做 5 分钟进程内缓存，避免每次进页面扫表；后台复核举报 / 处置账号后最多延迟一个 TTL 生效。需要立即刷新时调用 `app.services.security_center.clear_governance_cache()`。

### 静态内容

优先读 `admin_config_snapshot.platform_content`：

- `security_hero_title` / `security_hero_subtitle` / `security_hero_note`
- `security_support_title` / `security_support_description`
- `security_risk_notice`

键缺失时回退到 `app/services/security_center.py` 里的常量，后台不改配置也能正常出页面。

反诈卡片的 `type` 必须是 `GET /public/articles/{type}` 支持的键（当前只有 `cheat_notice` 属反诈类），否则用户点开必然 404。

### 前端映射

`api/security.uts` 的 `mapSecurityCenter()` 负责 snake_case → camelCase，并对缺失字段做兜底；`governance` 为 `null` 时页面走「暂无本月治理数据」分支。前端契约测试 `xuanshiai-vue/tests/test-security-center-contract.js` 与本文件的口径必须同步。
