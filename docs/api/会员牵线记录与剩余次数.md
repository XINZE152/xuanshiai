# 会员牵线记录与剩余次数接口

## 1. 查询会员牵线记录

**用途**：查询 CRM 会员详情中与该会员相关的全部牵线申请记录。

**基本信息**

- URL：`/api/v1/admin/members/{member_id}/match-records`
- Method：`GET`
- 登录：需要管理员登录
- 权限：`matchmaker.member.read`
- Headers：`Authorization: Bearer <access-token>`
- Content-Type：无请求体；响应为 `application/json`
- 成功状态码：`200`

**请求参数**

| 参数 | 位置 | 类型 | 必填 | 默认/范围 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `member_id` | path | integer | 是 | >=1 | 会员用户 ID；不存在返回 404 |
| `page` | query | integer | 否 | 1，1-1000 | 页码 |
| `page_size` | query | integer | 否 | 20，1-100 | 每页数量 |

请求示例：`GET /api/v1/admin/members/101/match-records?page=1&page_size=20`

无请求体。非法示例：`member_id=0` 或 `page_size=101` 返回 `422`。

**返回参数**

| 字段 | 类型 | 必返 | 含义 |
| --- | --- | --- | --- |
| `items` | array | 是 | 牵线记录；无数据时为空数组 |
| `items[].id` | integer | 是 | `match_apply` 记录 ID |
| `items[].from_user_id` | integer | 是 | 发起牵线的会员 ID |
| `items[].to_user_id` | integer | 是 | 被牵线会员 ID |
| `items[].target_nickname` | string/null | 是 | 相对于当前会员的对方昵称；昵称为空时为 null |
| `items[].message` | string/null | 是 | 牵线留言 |
| `items[].status` | integer | 是 | 申请状态，具体枚举以 `match_apply` 业务定义为准 |
| `items[].responded_at` | datetime/null | 是 | 对方响应时间 |
| `items[].created_at` | datetime/null | 是 | 创建时间 |
| `page` | integer | 是 | 当前页 |
| `page_size` | integer | 是 | 当前页大小 |
| `total` | integer | 是 | 总记录数 |
| `has_more` | boolean | 是 | 是否还有下一页 |

成功响应：

```json
{
  "items": [{
    "id": 9001,
    "from_user_id": 101,
    "to_user_id": 202,
    "target_nickname": "李女士",
    "message": "后台手工牵线",
    "status": 1,
    "responded_at": "2026-09-20T10:00:00",
    "created_at": "2026-09-20T09:30:00"
  }],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "has_more": false
}
```

**使用方法与业务规则**

- 前端进入会员详情后调用；分页只影响当前查询，不改变记录状态。
- 记录按 `created_at` 倒序、ID 倒序返回。
- 该接口只读，不扣减牵线次数，不要求 `Idempotency-Key`。
- `404` 表示会员不存在；会员存在但没有记录时返回空分页。

## 2. 查询会员剩余牵线次数

**用途**：查询指定会员的牵线次数账户，供会员详情页展示剩余、已使用和已退还次数。

**基本信息**

- URL：`/api/v1/admin/members/{member_id}/match-quota`
- Method：`GET`
- 登录：需要管理员登录
- 权限：`matchmaker.member.read`
- Headers：`Authorization: Bearer <access-token>`
- Content-Type：无请求体；响应为 `application/json`
- 成功状态码：`200`

**请求参数**

| 参数 | 位置 | 类型 | 必填 | 默认/范围 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `member_id` | path | integer | 是 | >=1 | 会员用户 ID；不存在返回 404 |

请求示例：`GET /api/v1/admin/members/101/match-quota`

无请求体。非法示例：`member_id=0` 返回 `422`。

**返回参数**

| 字段 | 类型 | 必返 | 空值含义 | 含义 |
| --- | --- | --- | --- | --- |
| `user_id` | integer | 是 | 不为空 | 会员 ID |
| `available_count` | integer | 是 | 无账户时为 0 | 当前剩余可用次数 |
| `used_count` | integer | 是 | 无账户时为 0 | 已消耗次数 |
| `refunded_count` | integer | 是 | 无账户时为 0 | 已退还次数 |
| `updated_at` | datetime/null | 是 | 无账户时为 null | 次数账户最近更新时间 |

成功响应（已有账户）：

```json
{
  "user_id": 101,
  "available_count": 5,
  "used_count": 3,
  "refunded_count": 1,
  "updated_at": "2026-09-20T10:00:00"
}
```

无账户响应：

```json
{
  "user_id": 101,
  "available_count": 0,
  "used_count": 0,
  "refunded_count": 0,
  "updated_at": null
}
```

**使用方法与业务规则**

- 前端可与牵线记录接口并行调用；该接口只读，不创建账户、不扣次数。
- 牵线服务实际扣减 `available_count` 并增加 `used_count`；退款增加 `available_count` 和 `refunded_count`。
- 无额度账户不是错误，统一返回 0 值，便于前端直接展示。
- 会员不存在返回 `404`；未登录或无权限分别由统一鉴权返回 `401/403`。

## 错误契约

| HTTP | 触发条件 | 前端处理 |
| --- | --- | --- |
| `401` | 未登录或 Token 无效 | 引导重新登录 |
| `403` | 缺少 `matchmaker.member.read` 权限 | 提示无权查看 |
| `404` | `member_id` 对应会员不存在 | 刷新列表或提示会员已不存在 |
| `422` | 路径或分页参数类型/范围错误 | 按参数错误提示并修正请求 |

错误响应示例：`{"detail":"会员不存在"}`。

## 3. 统一修改会员信息

**用途**：后台一次提交修改截图中的会员基础信息、认证状态和隐私设置；未提交字段保持不变。

**基本信息**

- URL：`/api/v1/admin/members/{member_id}/profile`
- Method：`PATCH`
- 登录：需要管理员登录
- 权限：`matchmaker.member.manage`
- Headers：`Authorization: Bearer <access-token>`、`Content-Type: application/json`
- 成功状态码：`200`

**请求参数**

| 参数 | 位置 | 类型 | 必填 | 规则 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `member_id` | path | integer | 是 | >=1 | 会员 ID |
| `nickname` | body | string/null | 否 | <=64 字符 | 昵称 |
| `avatar` | body | string/null | 否 | <=255 字符 | 头像 URL |
| `status` | body | integer | 否 | 1正常/2冻结/3注销 | 账号状态 |
| `is_married` | body | integer | 否 | 0未知/1未婚/2离异/3丧偶 | 婚姻状态 |
| `is_single_pledge` | body | boolean | 否 | true/false | 单身承诺开关 |
| `real_name` | body | string/null | 否 | <=64 字符 | 实名姓名 |
| `auth_status` | body | integer | 否 | 0-3 | 实名认证状态 |
| `house_verified` | body | integer | 否 | 0-3 | 房产认证状态 |
| `education_verified` | body | integer | 否 | 0-3 | 学历认证状态 |
| `match_status` | body | integer | 否 | 1-5 | 交友/展示状态 |
| `only_vip_can_see_detail` | body | boolean | 否 | true/false | 仅 VIP 可看详细资料 |
| `show_profile` | body | boolean | 否 | true/false | 是否展示个人资料 |
| `reason` | body | string | 是 | 1-255 字符 | 修改理由，写入审计 |

请求示例：

```http
PATCH /api/v1/admin/members/101/profile
Authorization: Bearer <access-token>
Content-Type: application/json
```

```json
{"auth_status":2,"house_verified":2,"only_vip_can_see_detail":true,"reason":"人工复核通过"}
```

非法示例：`{"reason":""}` 返回 `422`；未提供任何待修改字段也返回 `422`。

**返回参数**：`user_id` 为会员 ID；`updated_fields` 为本次实际更新字段名数组；`reason` 为审计理由。

```json
{"user_id":101,"updated_fields":["auth_status","house_verified","only_vip_can_see_detail"],"reason":"人工复核通过"}
```

**业务规则**：接口在同一事务中更新对应表并写入 `business_audit_log`；会员不存在返回 `404`，无权限返回 `403`，并发修改按用户行锁串行化。该接口不修改线上/线下 VIP 套餐和牵线次数，VIP 与牵线次数分别使用专用接口。

## 4. 修改会员剩余牵线次数

**基本信息**：`PATCH /api/v1/admin/members/{member_id}/match-quota`；需要管理员登录和 `matchmaker.member.manage` 权限；请求/响应均为 `application/json`。

**请求体**：`available_count`（integer，0-1000000，修改后的剩余次数，必填）；`reason`（string，1-255 字符，必填）。

```json
{"available_count":12,"reason":"运营补发牵线次数"}
```

**返回示例**：

```json
{"user_id":101,"available_count":12,"used_count":3,"refunded_count":1,"updated_at":"2026-09-22T08:00:00"}
```

接口语义是“直接设置剩余值”，不是增量加减；使用行锁更新或创建 `matchmaker_service_quota` 账户，并记录修改前后值及理由。会员不存在返回 `404`，参数非法返回 `422`，无权限返回 `403`。

## 兼容性与变更记录

- `match-records` 原有 URL、请求参数和字段保持不变，仅新增明确的响应模型约束，属于兼容性增强。
- `match-quota` 为新增接口，不影响现有客户端。
- 2026-09-22：新增 `PATCH /admin/members/{member_id}/profile` 和 `PATCH /admin/members/{member_id}/match-quota`；旧查询接口保持兼容。
