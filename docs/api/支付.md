# 测试支付、爆灯和置顶接口

接口前缀：`/api/v1`。测试支付仅允许 `development`/`testing` 环境，不调用微信或其他第三方支付。

## 通用测试支付

### `POST /api/v1/payments/test/pay`

Header：`Authorization: Bearer <token>`。

请求：

```json
{"order_no":"TEST...","success":true}
```

`success=false` 会将待支付订单置为支付失败；`success=true` 会将订单置为支付成功并触发对应履约。重复请求已支付订单返回相同成功状态，不重复开通权益。响应字段：`order_no`、`status`（0待支付、1成功、2失败）、`transaction_id`、`payment_required`、`fulfilled`。

## 置顶

| Method | URL | 说明 |
|---|---|---|
| GET | `/api/v1/boost/packages` | 查询测试套餐 |
| GET | `/api/v1/users/me/boost/status` | 查询当前置顶状态 |
| POST | `/api/v1/boost/orders` | 创建订单，需 `Idempotency-Key` |
| GET | `/api/v1/boost/orders/{order_no}` | 查询本人订单 |

套餐编码由服务端返回：`boost_1d`、`boost_7d`、`boost_30d`。创建订单请求为 `{"package_code":"boost_7d"}`。测试支付成功后，`user_boost` 写入当前用户的有效置顶记录，并影响推荐/广场排序。

## 爆灯支付

### `POST /api/v1/spotlights/payments`

请求体：`{"target_user_id":23}`，需 `Idempotency-Key`。金额由后端决定，当前测试金额为 5.00，不能由前端传入覆盖。支付订单创建后调用通用测试支付接口；成功履约后写入爆灯记录并通知目标用户。

### `GET /api/v1/spotlights/payments/{order_no}`

只允许订单创建者查询。原 `POST /api/v1/discovery/superlikes/{target_id}` 仍是免费额度爆灯，两者是不同业务。

## 微信支付回调（D-21，2026-10-12 批次 B）

### `POST /api/v1/payments/wechat/callback`

请求体（`WechatPaymentCallback`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `order_no` | 是 | 本系统支付订单号 |
| `transaction_id` | 是 | 微信侧交易号 |
| `signature` | 是 | 回调签名（十六进制 HMAC-SHA256） |
| `amount` | 条件必填 | `wechat_payment_mode=real` 时**必填**，用于金额一致性校验；mock 模式可省略 |

**验签口径**

```
payload   = f"{order_no}|{transaction_id}|{amount:.2f}"     # amount 为 None 时取空串
signature = HMAC-SHA256(key=secret, msg=payload).hexdigest()
```

- `secret` 来源：`real` 模式用 `WECHAT_PAYMENT_SIGN_KEY`（未配置 → **503**，不进入业务逻辑）；`mock` 模式用 `WECHAT_PAYMENT_MOCK_SECRET`（默认 `mock-payment-secret`）。
- 比对使用 `secrets.compare_digest`（常量时间），**签名不符 → 401 且不触碰数据库**。
- 签名正确后才进入业务：订单不存在 → 404；**重复回调幂等**（直接返回既有履约结果，不重复开通权益）；订单状态不可履约 → 409；`real` 模式金额与订单不一致 → 409。
- 所有 404 / 409 异常均落 `business_audit_log`，`action = 'payment.callback.rejected'`（点号分隔，与 `模块.对象.动作` 命名一致），便于对账与排障。

**幂等与安全边界**

- 回调路径**不依赖** `Idempotency-Key`（第三方回调不带该头），幂等靠「订单号 + 已履约状态」判定。
- 回调**不做**数据范围收口（属系统间调用，非后台人工操作）。

## 错误处理

- `401`：未登录；或支付回调**验签失败**。
- `403`：测试支付在非开发/测试环境调用，或无权操作目标资源。
- `404`：套餐、目标用户或订单不存在。
- `409`：订单已失败/已退款/当前状态不可支付，或幂等键对应不同业务请求；或回调**金额与订单不一致**。
- `422`：参数格式、范围或套餐编码错误。
- `503`：仅真实支付链路的外部服务不可用；测试支付不依赖微信。`real` 模式缺少 `WECHAT_PAYMENT_SIGN_KEY` 时回调同样返回 503。

## 回归测试

`tests/test_payment_callback_verification.py`（12 条）：伪造签名 401 且不写库、金额不一致 409、重复回调幂等、订单不存在 404、缺 `WECHAT_PAYMENT_SIGN_KEY` 503、异常落 `payment.callback.rejected` 审计。
> 2026-10-12 变更：当前仅支持 development/testing 的 mock HMAC 回调。`real` 模式 fail-closed，固定返回 503，不受理 mock HMAC，也不履行订单。微信支付 v3 官方通知的原始请求体、时间戳、nonce、平台证书/公钥验签、API v3 密钥解密、商户号/订单号/金额/交易状态校验尚未接入。禁止将 mock 签名用于生产。
>
> **2026-10-30 更新**：以上描述仅适用于旧 `/payments/wechat/callback`。新的真实链路使用 `/payments/wechat/notify`，已接入 APIv3 验签、平台证书/公钥、AES-256-GCM 解密、金额/商户号/状态校验；旧接口继续保留给 mock 测试。

# 微信支付 APIv3 预支付与回调（2026-10-30 新增）

> 适用范围：`WECHAT_PAY_MODE=real`。旧 `/payments/wechat/callback` 继续服务 mock 测试，不用于生产。
> 配置项见 `.env.example` 的 `WECHAT_PAY_*`；所有金额由服务端按订单金额计算，前端不得传金额。

## `POST /api/v1/payments/orders/{order_no}/prepay`

**用途**：为当前用户的待支付订单创建微信 JSAPI 预支付单。

**Method**：`POST`

**是否需要登录**：是（Bearer Token）

**所需角色**：普通登录用户

**Content-Type**：无请求体

**成功状态码**：200

### 路径参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `order_no` | string(8-64) | 是 | 本地支付订单号；必须是当前用户创建、状态为待支付、未过期、`channel=wechat` 的订单 |

### 返回参数

| 字段 | 类型 | 必返 | 说明 |
|---|---|---|---|
| `app_id` | string | 是 | 小程序 AppID，前端映射为 `appId` |
| `time_stamp` | string | 是 | 秒级时间戳字符串，前端映射为 `timeStamp` |
| `nonce_str` | string | 是 | 随机字符串，前端映射为 `nonceStr` |
| `package` | string | 是 | 固定格式 `prepay_id=wx...` |
| `sign_type` | string | 是 | 固定 `RSA`，前端映射为 `signType` |
| `pay_sign` | string | 是 | RSA 签名，前端映射为 `paySign` |

成功响应：

```json
{
  "app_id": "wx1234567890",
  "time_stamp": "1761800000",
  "nonce_str": "9f2c1d3e4a5b6c7d",
  "package": "prepay_id=wx301234567890abcdef",
  "sign_type": "RSA",
  "pay_sign": "base64-rsa-signature"
}
```

### 使用方法与业务规则

1. 前端先调用会员/爆灯/置顶/服务单创建订单接口，拿到 `order_no`；
2. 调用本接口获取参数后，再调用 `wx.requestPayment`；
3. 支付结果**以服务端回调为准**，前端 `success` 只用于刷新页面；
4. 订单必须属于当前用户、状态为 0、未过期、`channel=wechat`；
5. 用户必须已有 `users.openid`，否则返回 409 `WECHAT_OPENID_REQUIRED`；
6. `WECHAT_PAY_MODE!=real`、微信网络异常、微信 4xx/5xx 返回 503；
7. 同一 `order_no` 重复调用会复用微信侧商户订单号；前端不要自行生成订单号。

### 错误

| HTTP | 场景 | 响应示例 |
|---:|---|---|
| 401 | 未登录/Token 失效 | `{"detail":"请先登录"}` |
| 404 | 订单不存在或不属于当前用户 | `{"detail":"订单不存在"}` |
| 409 | 订单已支付/已过期/渠道不符/openid 缺失 | `{"detail":"订单当前不可支付"}` |
| 503 | 微信支付未启用/网络异常/微信错误 | `{"detail":"微信支付请求超时"}` |

## `POST /api/v1/payments/wechat/notify`

**用途**：接收微信支付 APIv3 支付/退款通知。

**Method**：`POST`

**是否需要登录**：否，必须通过微信支付平台证书/公钥验签

**Content-Type**：`application/json`（微信原始 body，服务端不先做 Pydantic 解析）

**成功状态码**：204（无响应体）

### 请求头（微信生成）

| Header | 必填 | 说明 |
|---|---|---|
| `Wechatpay-Timestamp` | 是 | 秒级时间戳，超过 5 分钟拒绝 |
| `Wechatpay-Nonce` | 是 | 随机字符串 |
| `Wechatpay-Signature` | 是 | 平台证书/公钥签名 |
| `Wechatpay-Serial` | 是 | 平台证书序列号或公钥 ID |

### 处理规则

1. 读取 `await request.body()` 原始字节；
2. 校验时间戳、平台证书/公钥签名；
3. 用 APIv3 密钥 AES-256-GCM 解密 `resource`；
4. 以 `notify_id` 写入 `payment_notify_log`，唯一键防重放；
5. `event_type=TRANSACTION.SUCCESS` 时调用 `PaymentOrderService.mark_paid`；
6. 校验 `mchid/appid/trade_state=SUCCESS/amount.total/currency=CNY`；
7. 金额按「分」比较，订单金额按元 × 100 转换；
8. 已支付订单重复通知幂等返回 204；
9. 本轮只落订单支付状态，不执行会员/爆灯/服务单履约；履约由第三轮 Dispatcher 处理。

### 错误

| HTTP | 场景 | 响应 |
|---:|---|---|
| 401 | 签名校验失败/时间戳过期/解密失败 | `{"code":"FAIL","message":"签名验证失败"}` |
| 409 | 金额不一致、商户号/AppID 不匹配、订单状态不可支付、处理异常 | `{"code":"FAIL","message":"..."}` |
| 204 | 处理成功或重复通知 | 无响应体 |

> 配置要求：`WECHAT_PAY_MODE=real`，且 `WECHAT_PAY_MCH_ID / WECHAT_PAY_APP_ID / WECHAT_PAY_SERIAL_NO / WECHAT_PAY_PRIVATE_KEY(_PATH) / WECHAT_PAY_API_V3_KEY / WECHAT_PAY_NOTIFY_URL` 齐全；staging/production 回调地址必须 HTTPS。

## `POST /api/v1/admin/finance/orders/{order_id}/refunds`

**用途**：后台发起真实微信退款。

**Method**：`POST`

**权限**：后台账号，需 `finance.write`

**敏感操作**：`Idempotency-Key`（8-128）+ `confirm=true`

**成功状态码**：201

请求体：

```json
{"amount": 68.00, "reason": "用户申请退款"}
```

返回字段：`refund_no`、`order_no`、`amount`、`refund_type`（FULL/PARTIAL）、`status`、`wechat_refund_id`。

规则：

1. 锁订单行，校验订单状态必须为已支付、渠道为 `wechat`；
2. 可退余额 = 订单金额 − 已占用退款（CREATED/PROCESSING/SUCCESS）；
3. 先写 `payment_refund(CREATED)` 并提交事务，再调微信退款；
4. 微信超时/5xx 保留 CREATED，后续通过 `RefundService.query_refund` 补偿；
5. 退款成功后更新订单 `refund_status/refunded_amount`，全额退款置 `status=3`；
6. 投递 `REVOKE:{refund_no}` 到 `payment_fulfillment_job`，由 Worker 回收权益。

错误：`409` 订单状态/金额/渠道不符；`502` 微信退款失败；`503` 支付网关未启用。

## `POST /api/v1/payments/wechat/refund-notify`

**用途**：接收微信退款 APIv3 通知。

**Method**：`POST`

**是否需要登录**：否，使用平台证书/公钥验签

**成功状态码**：204

处理规则：

1. 与支付回调相同的验签、解密、`notify_id` 防重放；
2. 按 `out_refund_no` 锁定退款单；
3. 更新退款状态、`notify_id`、成功时间/失败原因；
4. 退款成功时更新订单累计退款金额与状态；
5. 投递 `REVOKE:{refund_no}` 履约回收任务；
6. 异常返回 401/409 `{"code":"FAIL","message":"..."}`。

## 对账 CLI

```bash
# 默认核对 UTC+8 昨日交易账单
python -m app.workers.reconcile_worker --once

# 指定日期
python -m app.workers.reconcile_worker --once --bill-date 2026-10-29

# 每日循环（建议用 systemd timer 调用 --once）
python -m app.workers.reconcile_worker --interval 86400
```

对账结果写入 `payment_reconcile_batch`，差异写入 `payment_reconcile_diff`（`LOCAL_ONLY / REMOTE_ONLY / AMOUNT_MISMATCH / STATUS_MISMATCH / REFUND_MISMATCH`）。
