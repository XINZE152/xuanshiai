# 直播相亲接口

**版本**：R0.2 可靠事件与治理收口，2026-09-16
**前缀**：`/api/v1`  
**认证**：除场次列表和详情外，HTTP 接口使用 `Authorization: Bearer <access_token>`。

## 一、统一规则

- 状态按 `DRAFT -> SCHEDULED -> CHECK_IN -> WARMUP -> OPEN -> INTRO -> MATCHMAKER_QA -> HEART_LIGHT -> SELECT -> GUIDED_EXCHANGE -> DOUBLE_CONFIRM -> APPLY_KNOW -> CLOSED` 推进；多数进行中状态允许紧急关闭。
- 预约要求实名、人脸认证、年满 18 周岁且账号未被封禁。
- 签到只能在 `CHECK_IN` 环节执行，且必须先提交通过的设备检测结果。
- 主持、红娘和审核员权限由服务端场次角色决定，客户端不能自报角色。
- `HEART_LIGHT`、`SELECT`、`CONFIRM` 分别只能在对应环节执行，双方必须都在舞台上；选择要求先亮灯，确认要求先选择。
- 互动接口必须提交 8 至 128 字符的 `Idempotency-Key`。
- TRTC 凭证只发给有效场次角色或已上台嘉宾；`LIVE_ENABLED=false` 或腾讯配置缺失时返回 `503`。
- TRTC 凭证要求腾讯房间资源为 `CONFIGURED/ACTIVE`，并按用户和场次限制为每分钟 10 次（可配置）。
- 服务端腾讯云控制面通过 Provider 适配器调用官方 Python SDK；客户端媒体进房仍由客户端 TRTC SDK 完成。
- 生产环境必须使用 `LIVE_PROVIDER=tencent`、CAM 子账号和回调密钥；`mock` 只允许开发/测试环境。

## 二、场次查询

### 查询场次列表

**基本信息**：`GET /api/v1/live/sessions`；无需登录；成功状态码 `200`。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 默认值 | 校验与含义 | 示例 |
|---|---|---|---|---|---|---|
| `status` | query | string | 否 | 无 | 按场次状态过滤；不传时排除草稿 | `SCHEDULED` |

**请求体示例**：无请求体。非法示例：`status=UNKNOWN` 返回 `422`。

**返回参数**：`items` 为场次数组；每项包含 `id`、`title`、`city_code`、`scheduled_at`、`status`、`state_version`、`host_user_id`、`max_stage_seats`、`recording_enabled`、`rules_text`、`created_at`、`updated_at`；`total` 为匹配总数。

**返回示例**：

```json
{"items": [], "total": 0}
```

### 查询场次详情

**基本信息**：`GET /api/v1/live/sessions/{session_id}`；无需登录；成功状态码 `200`。

**请求参数**：`session_id` 位于 path，整数，必填，最小值 1，表示直播场次 ID。

**请求体示例**：无请求体。非法示例：`session_id=0` 返回 `422`。

**返回参数**：同列表中的单个场次对象。场次不存在返回 `404`。

## 三、预约与签到

### 预约场次

**基本信息**：`POST /api/v1/live/sessions/{session_id}/reservations`；需要登录；成功状态码 `201`。

**请求参数**：`session_id` 为必填 path 整数；Header 必须包含有效 Bearer Token。无请求体。

**返回参数**：预约记录包含 `id`、`session_id`、`user_id`、`status`、`device_check_passed`、`checked_in_at`、`created_at`、`updated_at`。

**业务规则**：只允许在 `SCHEDULED` 或 `CHECK_IN` 状态预约；重复预约幂等；已取消预约可恢复。

**错误**：`403` 未实名、未通过人脸、未成年或账号受限；`404` 场次不存在；`409` 当前状态不可预约。

### 设备检测、签到和取消

**基本信息**：

- `POST /api/v1/live/sessions/{session_id}/device-check`
- `POST /api/v1/live/sessions/{session_id}/check-in`
- `DELETE /api/v1/live/sessions/{session_id}/reservations`

均需要登录。设备检测请求体为 `{"passed": true}`，`passed` 为必填 boolean；签到和取消无请求体。

**业务规则**：签到只允许 `CHECK_IN`；取消后的预约不能检测或签到；已签到用户不能通过取消预约退出，应走后续离场能力。

**错误**：`404` 预约不存在；`409` 环节不符、预约已取消、设备未通过或已签到。

## 四、主持控制

### 推进场次状态

**基本信息**：`POST /api/v1/live/host/sessions/{session_id}/transition`；需要主持、红娘或审核员角色；成功状态码 `200`。

**请求体**：

```json
{"to_status": "CHECK_IN", "expected_version": 1, "reason": "开放签到"}
```

`to_status` 必须属于状态字典；`expected_version` 为必填正整数，用于乐观锁；`reason` 可选，最长 255 字符。

**返回参数**：返回迁移后的完整场次对象。

**错误**：`403` 无控制权限；`404` 场次不存在；`409` 迁移非法或版本冲突。版本冲突时前端必须刷新详情，不得盲目重试。

### 邀请用户上台

**基本信息**：`POST /api/v1/live/host/sessions/{session_id}/invitations`；需要场次控制权限；成功状态码 `201`。

**请求体**：`{"user_id": 123, "seat_no": 1}`。`user_id` 为正整数；`seat_no` 范围 1 至 8，且不能超过场次实际席位数。

**返回参数**：`session_id`、`seat_no`、`user_id`、`status=INVITED`、32 字符 `invitation_token`、`invitation_expires_at`。

**业务规则**：用户必须已签到且设备检测通过；同一用户不能同时占用或被邀请到多个席位；邀请 60 秒过期。

### 强制用户下台

**基本信息**：`POST /api/v1/live/host/sessions/{session_id}/stage/remove`；需要场次控制权限；成功状态码 `200`。

**请求体**：`{"user_id":123,"reason":"违反场次规则"}`；`user_id` 为正整数，`reason` 必填且长度 2 至 255 字符。

**返回参数**：`session_id`、`user_id`、`status=REMOVED`。服务端同时清空席位、写人工处置记录并广播事件。

**错误**：`403` 无控制权限；`409` 用户没有有效邀请且不在舞台。

### 设置或解除场内限制

**基本信息**：`PUT /api/v1/live/host/sessions/{session_id}/restrictions`；需要场次控制权限；成功状态码 `200`。

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 校验与含义 | 合法示例 | 非法示例 |
|---|---|---|---|---|---|---|
| `session_id` | path | integer | 是 | 正整数，直播场次 ID | `12` | `0` |
| `user_id` | body | integer | 是 | 正整数，且必须是本场参与用户 | `123` | `-1` |
| `restriction_type` | body | string | 是 | `MUTE` 或 `RTC_BLOCK` | `RTC_BLOCK` | `BAN` |
| `enabled` | body | boolean | 否 | `true` 设置、`false` 恢复 | `true` | `1` |
| `reason` | body | string | 是 | 2 至 255 字符 | `持续泄露隐私` | 空字符串 |

**请求示例**：

```json
{"user_id":123,"restriction_type":"RTC_BLOCK","enabled":true,"reason":"持续泄露隐私"}
```

**返回参数**：`session_id`、`user_id`、`restriction_type`、`enabled`。`RTC_BLOCK` 生效时同时清理该用户的有效邀请或在台席位；`MUTE` 当前只形成业务权限和审计状态，腾讯服务端静音未验收。

**错误**：`403` 无控制权限；`404` 用户不是场次参与者；`422` 参数非法。

### 查询运营快照

**基本信息**：`GET /api/v1/live/host/sessions/{session_id}/operations`；需要场次控制权限；成功状态码 `200`；无请求体。

**返回参数**：`session_id`、`state_version`、`seats[]`、`registrations[]`、`reports[]`、`recent_actions[]`。列表分别表示当前席位、最多 200 条预约/候场、最近 100 条举报和最近 100 条人工处置，不包含联系方式。

**返回示例**：

```json
{"session_id":12,"state_version":5,"seats":[],"registrations":[],"reports":[],"recent_actions":[]}
```

**错误**：`403` 无控制权限；`404` 场次不存在。

### 分配场次角色

**基本信息**：`PUT /api/v1/admin/live/sessions/{session_id}/roles`；需要平台管理员；成功状态码 `200`。

**请求体**：`{"user_id":123,"role_code":"MATCHMAKER","enabled":true}`；`role_code` 仅支持 `MATCHMAKER`、`MODERATOR`。

**返回参数**：`session_id`、`user_id`、`role_code`、`enabled`。重复请求更新现有角色状态并写业务审计。

## 五、嘉宾互动

### 响应邀请

**基本信息**：`POST /api/v1/live/sessions/{session_id}/invitations/respond`；需要登录。

**请求体**：`{"invitation_token":"<32字符令牌>","decision":"accept"}`；`decision` 仅支持 `accept` 或 `reject`。

**返回参数**：`session_id` 与 `status`；接受为 `ON_STAGE`，拒绝为 `EMPTY`。

**错误**：`409` 场次状态不允许、邀请过期、令牌不匹配或邀请已处理。

### 主动离开舞台

**基本信息**：`POST /api/v1/live/sessions/{session_id}/stage/leave`；需要登录；无请求体；成功状态码 `200`。

**返回参数**：`session_id`、`user_id`、`status=LEFT`。服务端清空当前用户席位并广播离场事件；用户不在台上时返回 `409`。

### 提交亮灯、选择或确认

**基本信息**：`POST /api/v1/live/sessions/{session_id}/interactions`；需要登录；成功状态码 `201`；必须提交 `Idempotency-Key`。

**请求体**：`{"target_user_id":456,"interaction_type":"HEART_LIGHT"}`；类型仅支持 `HEART_LIGHT`、`SELECT`、`CONFIRM`。

**返回参数**：`id`、`session_id`、`actor_user_id`、`target_user_id`、`interaction_type`、`status`、`created_at`、`match_status`。非确认操作的 `match_status` 为 `null`；确认后为 `WAITING_CONFIRMATION` 或 `READY_FOR_APPLICATION`。

**业务规则**：不能选择自己；双方必须在台上；每一步校验前置步骤；拉黑或账号申请受限时拒绝互动。双方确认后只形成 `READY_FOR_APPLICATION`，不会自动创建私聊或返回联系方式。相同幂等键和相同请求返回原结果，键被其他请求占用返回 `409`。

### 举报用户

**基本信息**：`POST /api/v1/live/sessions/{session_id}/reports`；需要登录；成功状态码 `201`。

**请求体**：`target_user_id` 必填正整数；`category` 必须为 `HARASSMENT`、`PRIVACY`、`CONTENT`、`AUDIO_VIDEO`、`OTHER`；`description` 可选，最长 500 字符。

**返回参数**：`id` 和 `status=PENDING`。不能举报自己。

**业务规则**：举报双方必须属于当前场次；举报说明复用平台文字审核；命中拒绝规则时返回 `422`，审核服务不可用时按平台内容审核策略处理。

## 六、腾讯 TRTC

### 领取 RTC 凭证

**基本信息**：`POST /api/v1/live/sessions/{session_id}/rtc-ticket`；需要登录；无请求体；成功状态码 `200`。

**返回参数**：`sdk_app_id`、`room_id`、`user_id`、`user_sig`、`expires_in`、`role`。`user_sig` 是敏感短时凭证，禁止写日志、缓存到公共存储或转发给其他用户。

**错误**：`403` 没有 RTC 资格、账号受限或本场 `RTC_BLOCK`；`409 LIVE_ROOM_NOT_READY` 场次资源未配置、尚未开放或已关闭；`429 LIVE_TICKET_RATE_LIMITED` 请求过频；`503` 直播开关、腾讯配置或生产 Redis 不可用。

### 腾讯回调

**基本信息**：`POST /api/v1/live/callbacks/tencent`；不使用用户登录；不展示在 OpenAPI。

**Headers**：`X-Tencent-Timestamp` 和 `X-Tencent-Signature` 必填。当前项目级契约使用 `<timestamp>.<raw_body>` 作为 HMAC-SHA256 输入；时间偏差默认不得超过 300 秒。真实接入前必须以已开通腾讯产品的官方回调文档和样例为准。

**请求体**：JSON，默认最多 64 KiB；必须包含事件 ID、白名单内事件类型，可包含房间 ID。事件白名单由 `TENCENT_LIVE_CALLBACK_EVENT_TYPES_RAW` 配置。

**返回参数**：`{"accepted": true}`。回调按供应商事件 ID 幂等保存，只持久化事件标识、类型、场次和 payload 哈希，不保存原始敏感 payload。

**错误**：`401` 验签失败、时间戳非法或过期；`413` 请求体过大；`422` JSON、事件 ID、事件类型或房间 ID非法；`503` 回调密钥未配置。

### 变更记录（2026-09-13）

- 新增 `LIVE_PROVIDER`、腾讯 `SecretId`、地域、SDK 超时/重试和能力开关配置。
- 保留 `rtc-ticket` 原有字段和路径；新增 Provider/房间资源状态为服务端内部能力，不影响旧客户端。
- 场次关闭时，Tencent Provider 幂等调用 TRTC `DismissRoom`，结果写入 `live_provider_resource`；调用失败不会回写为腾讯成功状态。
- 腾讯 SDK 尚未在本地凭据或真实腾讯环境完成联调，混流、录制、CSS/CDN 仍保持关闭。

## 七、业务 WebSocket

连接地址：`ws://<host>/api/v1/live/sessions/{session_id}/events?token=<access_token>&last_version=<event_version>`。

服务端在握手前校验 Token，以及用户是否已预约或拥有场次角色；失败关闭码 `1008`，数据库或 Redis 不可用关闭码 `1011`。`last_version>0` 时最多补发其后的 200 条持久事件，再发送 `session.snapshot`；事件使用单调递增的 `event_version`，场次状态仍使用 `state_version`。之后通过 Redis Pub/Sub 推送新事件；空闲时发送 `heartbeat`。

客户端保存最新 `event_version` 用于重连，并按 `event_id` 或 `event_version` 去重；Outbox 采用 at-least-once 投递，极端故障恢复时允许重复事件。若断线跨度超过补发上限，以快照和 HTTP 查询结果为权威状态。Outbox Worker 使用 `python -m app.workers.live_event_worker` 重试 Redis 发布。

## 八、当前限制

- 尚未接入腾讯云混流、CSS/CDN、录制控制和除房间关闭外的具体供应商事件到业务状态的完整映射。
- 已实现强制下台、场内 `MUTE/RTC_BLOCK` 状态、直播 Outbox、有限历史补发和运营快照；尚未实现腾讯真实静音/断流、完整运营巡查页及双确认后申请认识/联系方式交换。
- 以上能力不得以当前接口或 Mock 宣称完成，详见直播评估报告和修改方案清单。

## 九、变更记录（2026-09-16）

- 新增场内限制和运营快照接口。
- RTC ticket 增加房间资源状态、账号/场内限制和限流门禁。
- 互动响应新增可空 `match_status`，旧客户端忽略未知字段即可，属于向后兼容变更。
- WebSocket 新增可选 `last_version` 和 `event_version`；不传时仍按快照方式连接。
- 腾讯内部回调新增时间戳、体积和事件白名单校验；真实供应商启用前必须完成官方契约迁移。
