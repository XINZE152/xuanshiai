# 提现收款信息与防重

任务标识：WITHDRAWAL-MANUAL-20261116。

`POST /api/v1/finance/withdrawals` 要求用户 Bearer 登录，JSON 请求体为 `amount`（正数，最多两位小数）、`method`（`wechat`、`bank`、`alipay`）、`account` 和 `payee_name`。请求头 `Idempotency-Key` 必填，长度 8–128；相同账号、相同键与相同内容重试返回同一申请，不重复扣账；相同键内容不同返回 409。网络失败或 5xx 的结果可能未知，客户端必须保留原键并以同一内容重试，不得自动生成新键。

示例：`Idempotency-Key: withdrawal-example-123`，请求体 `{"amount":"0.01","method":"wechat","account":"example","payee_name":"示例"}`。成功状态码 201，返回现有 `WithdrawalResponse`：`id`、`account_type`、`account_id`、`amount`、`status`、`payee_masked`、`failure_reason`、`created_at`、`updated_at`。仅显示脱敏标识；完整收款信息使用单独的服务端 Fernet 密钥加密。

上线前必须配置持久保存的 `WITHDRAWAL_PAYEE_ENCRYPTION_KEY`（Fernet 密钥；不得与 JWT 密钥共用，变更会使历史记录不可读），并执行及验证 `20261116_01_withdrawal_payee` 迁移。密钥缺失或无效返回 503，不创建申请或扣余额。管理员可调用 `GET /api/v1/admin/finance/withdrawals/{id}/payee`，仅 `finance.write` 且在数据范围内的管理员可见，读取写审计。申请状态和扣款在同一事务中写入；拒绝时按现有规则退回余额。

错误：401 未登录，403 关闭提现或无权限，409 余额不足或同键内容不一致，422 参数错误、收款信息不完整或无幂等键，503 加密配置不可用。仅含脱敏标识的旧版请求会被拒绝，避免生成无法转账的申请。此流程为审核后人工转账，不触发微信商家转账。

服务端按后台财务配置检查总开关、对应人工提现方式开关和单笔最小/最大金额。手续费规则目前仅支持 `none`；配置为扣除手续费时拒绝新申请，避免按错误金额结算。配置缺失或金额范围无效时拒绝处理。

兼容性：`Idempotency-Key` 和完整收款信息从无改为必填，旧客户端须先升级，旧请求否则返回 422。`method`、`account`、`payee_name` 为新增字段；服务端旧版本不支持这些字段，前端必须等服务端和迁移就绪后才启用。
