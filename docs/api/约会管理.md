# 约会管理接口与部署说明

任务：DATE-MGMT-20261103。所有路径以 `/api/v1` 开头；请求使用 `Authorization: Bearer <用户令牌>`、`Content-Type: application/json`。工作台接口要求已启用的红娘工作台身份，普通红娘仅访问自己范围，组织/平台管理员按已有工作台数据权限访问。响应为原始 JSON 模型，204 无响应体；错误使用项目标准错误响应，校验错误为 422。

## 用户约见申请（沿用既有接口）

| 用途 | 方法及路径 | 请求与结果 |
| --- | --- | --- |
| 用户提交 | POST `/matchmaker/meetings/requests` | `{"target_user_id":63,"note":"希望周末见面"}`；201 返回申请模型 |
| 我的申请 | GET `/matchmaker/meetings/requests/mine` | 返回自己发出、收到的申请数组 |
| 接受/拒绝/关闭 | PATCH `/matchmaker/meetings/requests/{request_id}` | `{"status":"ACCEPTED"}` 或 `{"status":"DECLINED","reason":"暂不考虑"}`；返回更新后的申请 |
| 红娘基于服务单申请 | POST `/matchmaker/meetings/requests/from-service` | `{"service_id":1,"target_user_id":63,"note":"邀请见面"}`；201 返回申请 |

申请模型包括 id、user_id、target_user_id、matchmaker_id、service_id、organization_id、status、note、created_at、updated_at。用户提交要求已绑定手机号，消耗已有约见额度；未分配服务红娘为 409。新申请写入申请人最新有效分派中的红娘和组织；服务单申请要求服务单红娘仍是申请人当前归属红娘，否则 409。仅被邀请方可以接受/拒绝；申请人自行接受为 403。重复处理中申请为 409。已有约会安排后用户不能再改变申请结果，应由服务红娘处理。

## 红娘列表与分块

GET `/matchmaker/workbench/meeting-requests?page=1&page_size=100&search=申请人`

page 1–1000，page_size 1–100，search 最长 64 字符，匹配姓名/昵称或编号。响应示例：

```json
{
  "workflow_version": 2,
  "items": [{
    "id": 8, "status": "ACCEPTED", "matchmaker_name": "服务红娘", "note": "希望见面",
    "created_at": "2026-11-03T10:00:00", "updated_at": "2026-11-03T10:30:00",
    "applicant": {"user_id": 62, "nickname": "申请人", "avatar": null, "gender": 1, "is_vip": false},
    "target": {"user_id": 63, "nickname": "被邀请方", "avatar": null, "gender": 2, "is_vip": false},
    "meeting": null
  }],
  "page": 1, "page_size": 100, "total": 1, "has_more": false
}
```

旧申请未写归属时，按申请人最新有效分派回退查询；不回填或覆盖旧数据。有 meeting 时包括 id、status、scheduled_at、location、cancel_reason、follow_up_content。

| 分块 | 规则 |
| --- | --- |
| 全部 | 所有范围内申请；SUBMITTED 标未回应，CONTACTED 标联系中 |
| 约会失败 | 申请 DECLINED/CLOSED，或约会 CANCELLED/NO_SHOW |
| 待见面 | ACCEPTED 未排期，或已有待执行约会；旧 COMPLETED 缺跟进也在此补记录 |
| 完成约会 | 约会 COMPLETED 且存在关联跟进记录 |

等待见面指标进入待见面；约会管理、约见申请进入全部。每个分块均可添加约会。小程序拉齐分页后按分块和申请人搜索；分页失败显示错误，不显示假数据。

## 联系结果与排期

PATCH `/matchmaker/workbench/meeting-requests/{request_id}/status`，成功 204。

```json
{"status":"ACCEPTED","contacts_confirmed":true,"applicant_agreed":true,"target_agreed":true}
```

红娘代记双方同意时，三项确认缺一为 409；拒绝使用 `{"status":"DECLINED","reason":"对方暂不考虑"}`，原因必填最长 200；也支持 CONTACTED、CLOSED。终态不能回退。用户接受后自动出现在待见面，无需红娘重复代记接受。

POST `/matchmaker/workbench/meeting-requests/{request_id}/schedule`，仅 ACCEPTED 申请可以安排，成功 201：

```json
{"scheduled_at":"2030-11-04T18:00:00+08:00","location":"门店一楼会客区"}
```

时间必须晚于现在；带时区输入统一转换为北京时间，无时区输入视为北京时间，数据库沿用现有 DATETIME。地点去空白后长度 1–128。一个申请已有任何约会记录不能重复排期（409）；需要另行发起新约会。返回约会模型示例：

```json
{"id":12,"status":"SCHEDULED","scheduled_at":"2030-11-04T18:00:00","location":"门店一楼会客区","cancel_reason":null,"follow_up_content":null}
```

## 红娘主动添加约会（新增）

POST `/matchmaker/workbench/meetings`，成功 201 返回上面的约会模型。

```json
{
  "applicant_user_id":62,"target_user_id":63,
  "contacts_confirmed":true,"applicant_agreed":true,"target_agreed":true,
  "scheduled_at":"2030-11-04T18:00:00+08:00","location":"门店一楼会客区"
}
```

申请人必须在当前红娘名下，被邀请方须在可服务范围；越权统一 404。两人不能相同，三项确认必须全部为 true，否则 422。社交限制仍生效。创建 ACCEPTED 申请及排期在同一事务内完成，不调用用户提交入口、不扣用户申请额度；同一申请人的重复处理中约会被锁及冲突检查阻止（409）。确认项是红娘对已联系双方的业务确认。

## 跟进与完成

PATCH `/matchmaker/workbench/meetings/{meeting_id}/status`，成功 204：

```json
{"status":"COMPLETED","follow_up_content":"双方已按时见面，愿意继续了解，约定一周后回访。"}
```

跟进内容 1–2000 字，纯空白为 422；未到约会时间为 409。跟进写入现有 member_follow_up，并通过 business_audit_log 关联约会；跟进及 COMPLETED 同一事务提交，失败回滚。重复完成不重复建跟进。已完成不能回退，取消/爽约不能完成。

仍支持 REMINDED、CHECKED_IN；取消/爽约使用 `{"status":"CANCELLED","cancel_reason":"一方临时有事"}` 或 NO_SHOW，原因为必填最长 200。取消/爽约进入约会失败。404 表示记录不存在或无服务权限；401 登录失效，403 无工作台身份/业务交互受限，409 状态冲突，422 输入无效。

## 远端发布与验证

本批没有数据库结构变更，复用 meeting_request、meeting_record、member_follow_up、business_audit_log、resource_assignment；不迁移本地/远端数据。必须先拉取并部署本批后端、重启服务，再发布/重新编译前端。前端仍连接既定远端；不能用本地测试代表远端通过。

登录红娘后列表应返回 `workflow_version:2`。老后端缺此字段时，小程序提示流程未升级并阻止新流程写入。部署后用两个测试会员和其归属红娘验证：提交→全部未回应→拒绝进失败；重新提交→接受后进待见面→排期→时间到后填跟进→完成；红娘手动添加需三项确认。再检查其他红娘不可越权、重复点击不产生重复记录。现有客源 500 是另一修复项，见待完成事项。
