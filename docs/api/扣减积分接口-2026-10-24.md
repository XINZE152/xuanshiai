# 扣减积分接口（A12-积分）

> **⚠️ 2026-10-27 口径修复（A12 BUG 关闭）**：本文原写「发放/扣减写 `account_ledger`」的口径已作废。
> 因 `account_ledger` 是「余额」账本，导致后台**发放积分后会员列表「积分」列恒为 0、「余额」列反而 +1**。
> 现 `credit-grants` / `credit-deductions` **改写 C 端积分账本 `user_points`**（`type=5`、滚动余额、
> `source_type='admin_grant'`），发放/扣减即时反映到「积分」列，不再污染「余额」。详见下方第 0 节与
> `migrations/member_points_admin_source/`。历史误发到 `account_ledger` 的记录**不回填**。

> 变更日期：2026-10-24　关联清单：`后端接口缺失清单.md` 第 391 行「扣减积分：`credit-grants` 只能发放不能扣减」
> 口径：**与「发放积分」`credit-grants` 对称**，写 `user_points`（`type=5` 负数行），**不新建表**（仅给 `user_points` 附加两个可空列）。

## 0. 积分口径说明（2026-10-27 更新）

- **积分的唯一权威账本是 C 端 `user_points`**（滚动余额：每行存 `type/amount/balance/desc`，余额 = 最新一行 `balance`）。后台「发放积分 / 扣减积分」现直接写这张表。
- 后台发放/扣减写入：`type=5`（后台发放/扣减）、`source_type='admin_grant'`、`operator_id=操作人 users.id`、`desc=理由`。
- 「积分明细」页与会员列表 `points` 列**统一取 `user_points`**（发放/扣减即时可见、可核对）；列表 `balance` 列仍取 `account_ledger`，与积分互不串味。
- `user_points` 为承载后台来源，新增两个**可空列** `source_type` / `operator_id`（迁移 `migrations/member_points_admin_source/20261027_01`）；C 端既有行（签到/任务/邀请/兑换）`source_type` 为 NULL。
- 副作用（良性）：后台发放记录会出现在 C 端用户自己的积分流水里（用户应得可见）。
- 设计文档「积分不支持前端直接修改」指 C 端用户不可自改，不限制后台运营发放；本次为该约束的口径修正。

## 1. 扣减积分

**`POST /api/v1/admin/finance/credit-deductions`**

| 项 | 说明 |
|---|---|
| 权限 | `finance.write` |
| Content-Type | `application/json` |
| 状态码 | 成功 `201` |
| **敏感操作** | Header `Idempotency-Key`（8–128）且 Query `confirm=true`；**缺 `confirm` → `428`；缺/非法幂等键 → `422`。** |
| 原子性 | 扣减前对本批用户 `user_points` 最新行 `FOR UPDATE` 加行锁并校验余额充足，**任一不足整批 `409`，不产生部分扣减**（无流水账户视为余额 0） |

### 请求

Query：`confirm=true`（必填）
Header：`Idempotency-Key: <8-128 chars>`（必填）

Body `CreditDeductRequest`（字段与 `CreditGrantRequest` 对称）：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `target_type` | string | 是 | `all` \| `member` \| `verified` \| `matchmaker_team` | 扣减目标范围 |
| `user_ids` | array[int] | 条件 | `target_type=member` 必填，≤5000 | 指定会员 ID |
| `amount` | int | 是 | `>0`、`≤1000000` | **每人**扣减积分数 |
| `reason` | string | 是 | 1–20 字 | 扣减理由，记入审计 |

```http
POST /api/v1/admin/finance/credit-deductions?confirm=true
Idempotency-Key: credit-deduct-20261024-0001
Content-Type: application/json

{ "target_type": "member", "user_ids": [10086], "amount": 50, "reason": "违规扣除" }
```

### 响应 `CreditDeductResult`

| 字段 | 类型 | 说明 |
|---|---|---|
| `deducted_count` | int | 实际扣减账户数（去重） |
| `total_amount` | int | `deducted_count * amount` |
| `sample_ledger_ids` | array[int] | 前 10 条 `user_points.id` 样本（扣减行） |
| `target_user_ids` | array[int] | 命中 user_id 列表 |

### 错误码

| 状态码 | 场景 |
|---|---|
| `404` | 扣减目标为空 / `target_type` 非法 |
| `409` | 存在可用积分不足的用户，整批未执行（detail 附前 20 个 ID） |
| `428` | 缺 `confirm=true` |
| `422` | 缺/非法 `Idempotency-Key`，或参数越界 |
