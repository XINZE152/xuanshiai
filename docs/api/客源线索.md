# 客源线索接口

## 通用约定

所有接口前缀为 `/api/v1`，需要 `Authorization: Bearer <access-token>`，且后台账号必须具有 `customer_lead.manage` 或 `*` 权限。所有写入均记录操作者审计日志；不返回密码、令牌或未脱敏支付信息。

## `GET /admin/customer-leads`

**基本信息**：分页查询客源线索；成功状态 `200`；无请求体。

**请求参数**：`page`（query，默认 `1`，范围 `1..1000`）、`page_size`（默认 `20`，范围 `1..100`）、`status`（可选：`NEW/CONTACTED/INTENDED/CONVERTED/LOST/CLOSED`）、`source`（可选，最长 64 字符）、`matchmaker_id`（可选正整数）和 `search`（可选，最长 64 字符，按称呼、手机、微信模糊匹配）。非法示例：`page_size=101` 返回 `422`。

**请求示例**：`GET /api/v1/admin/customer-leads?page=1&page_size=20&status=NEW&search=张`，Header 为 `Authorization: Bearer <access-token>`；无请求体。

**返回参数**：`items[]` 每项包含 `id/name/phone/wechat/source/intention_level/status/matchmaker_id/organization_id/next_follow_at/converted_user_id/remark/created_by/created_at/updated_at`；`intention_level` 为 `1` 低、`2` 中、`3` 高；分页包含 `page/page_size/total/has_more`。空数据响应为 `{"items":[],"page":1,"page_size":20,"total":0,"has_more":false}`。

**使用方法与业务规则**：只读、可分页筛选；记录创建、分派、修改和跟进必须调用对应写接口。无数据不是错误。

**错误**：`401` 未登录；`403` 无客源管理权限；`422` 参数非法；`500` 查询失败。

## 写接口

`POST /admin/customer-leads` 创建线索，要求 `name/source` 与至少一个 `phone/wechat`；`PATCH /admin/customer-leads/{lead_id}` 修改基础字段；`PATCH /admin/customer-leads/{lead_id}/assignment` 分派有效服务红娘或启用门店；`POST /admin/customer-leads/{lead_id}/follow-ups` 写入跟进，要求 `method` 为 `PHONE/WECHAT/VISIT/OTHER`、`content` 长度 `1..2000`。这些接口均需相同权限、均有参数校验和审计日志。

**联系方式唯一性（2026-09-05）**：同手机号或同微信号（去首尾空白后比较，空串视为未提供）在"有效"线索（状态非 `LOST/CLOSED`）中全局唯一。创建与 PATCH 修改联系方式前均查重，命中返回 `409`（`{"detail":"该联系方式已存在客源线索（ID: <占用线索ID>）"}`），数据库层由 `active_phone/active_wechat` 生成列唯一索引兜底；弃海、已关闭线索不占用联系方式，可用同一联系方式重新录入。恢复弃海（`restore`）时若联系方式已被其它有效线索占用返回 `409`（`该客源的联系方式已被其他有效线索占用，无法恢复`）。

**变更记录（2026-08-17）**：客源线索所有路由统一增加 `customer_lead.manage` 权限校验；旧的管理员通配权限 `*` 继续兼容。

## 弃海闭环（新增，2026-08-17）

### `POST /admin/customer-leads/{lead_id}/abandon`

**用途**：将未入库、未关闭的客源安全放入弃海池。需登录和 `customer_lead.manage` 权限；`lead_id` 为正整数 path 参数，Body 为 `{"reason":"连续多次联系未回复"}`，`reason` 必填，长度 `1..500`。成功 `201`，返回 `id/lead_id/reason/abandoned_by/abandoned_at/restored_by/restored_at/restore_reason`；未恢复记录中的后三项为 `null`。

操作会将线索状态改为 `LOST`、清空服务红娘和下次跟进时间，并写入业务审计日志，不删除原线索、跟进或历史记录。已入库、已关闭或已在弃海池返回 `409`；无权限 `403`；不存在 `404`；参数非法 `422`。前端在成功后重新加载线索列表和弃海池，不应本地隐藏记录。

### `POST /admin/customer-leads/{lead_id}/restore`

**用途**：从弃海池恢复客源。权限和参数同弃海接口，Body 为 `{"reason":"客户重新主动联系"}`。成功 `200`，返回恢复后的完整客源对象；会保留弃海历史，写入恢复人、恢复时间、恢复原因，并把线索状态恢复为 `NEW`。非弃海客源返回 `409`。

### `GET /admin/customer-leads/abandoned` 与 `GET /admin/customer-leads/abandonments`

**用途**：前者查询当前仍在弃海池的记录，后者查询全部弃海和恢复历史。无请求体、无 query 参数，成功 `200` 返回上述弃海记录数组；空数组合法。均需要登录及 `customer_lead.manage`。当前版本按记录倒序返回，下一版本会增加与主列表一致的分页、关键词和数据范围过滤；前端应把返回当作只读审计数据，恢复必须调用恢复接口。

**兼容性**：全部为新增 URL，不修改原客源列表、详情、分派和跟进契约。

## 客源删除（A16，新增 2026-10-24）

删除均为**软删除**：写入 `customer_lead.deleted_at`/`deleted_by`，不物理抹除行。删除后该客源默认从列表、详情、统计、弃海池和联系方式查重中排除；其占用的手机号/微信号由生成列 `active_phone/active_wechat`（纳入 `deleted_at IS NOT NULL` 判定）自动释放，可用同一联系方式重新录入。删除属敏感写操作，必须同时携带 `Idempotency-Key` 请求头（8–128 字符）和 `?confirm=true`；缺 `confirm` 返回 `428`，缺/短幂等键返回 `422`。同键同载荷重放不会重复删除。前置条件：已执行迁移 `migrations/customer_lead_gaps/20261024_01_lead_soft_delete_and_source_up.sql`（或 `AUTO_INIT_DB` 已补列）；未迁移时删除接口返回 `503`（提示先执行迁移）而非 `500`。

### `DELETE /admin/customer-leads/{lead_id}`

**用途**：软删除单条客源。`lead_id` 为正整数 path 参数。成功 `204`，无响应体。越权、不存在或已删除均返回 `404`。写入审计 `action='customer_lead.delete'`。

### `POST /admin/customer-leads/batch-delete`

**用途**：批量软删除。Body `CustomerLeadBatchDeleteRequest`：`{"lead_ids": [1, 2, 3]}`，`lead_ids` 为 `1..200` 个正整数（空数组或超过 200 返回 `422`，重复自动去重）。成功 `200`，返回 `CustomerLeadBatchDeleteResult`：

| 字段 | 类型 | 含义 |
|---|---|---|
| `deleted` | int[] | 本次成功删除的 lead_id |
| `failed` | `{id:int, error:string}[]` | 越权/不存在/已删除的线索及原因（`客源不存在、已删除或越权`），不整体报错 |

**业务规则**：部分成功语义——四条范围收敛（D-16）内且未删除的进入 `deleted`，其余归入 `failed`；整个批次在**单事务**内完成，仅写**一份汇总审计**（`action='customer_lead.batch_delete'`）。同键重放直接返回首次结果。静态路径 `/batch-delete` 先于 `/{lead_id}` 注册。

**错误**：`401` 未登录；`403` 无权限；`404`（单条）不存在/越权；`422` 参数非法；`428` 缺 `confirm=true`；`503` 未迁移。

## 来源 / 标签字典（A14，新增 2026-10-24）

前端「管理来源 / 管理标签」抽屉的 CRUD 接口，契约路径为复数段、挂在 `/admin/customer-leads` 下（与只读下拉 `GET /admin/customer-leads/options` 的 `sources / tags` 分组同命名）。来源写入新建的 `customer_lead_source` 字典表（`AUTO_INIT_DB` 自动建表并播种与前端一致的 10 个默认来源 + `批量导入`，生产用 `migrations/customer_lead_gaps/...` 镜像）；标签复用既有 `customer_lead_tag` 表。字典为全局配置型数据，**不做数据范围收敛**；均需登录及 `customer_lead.manage`。与自由文本 `customer_lead.source` 的兼容：录入仍按名称写自由文本，两者按 `name` 对齐；字典项被有效客源引用时禁止删除。

两类接口结构对称（`{kind}` 取 `sources` 或 `tags`）：

| 方法 | 路径 | 用途 | 成功状态 |
|---|---|---|---|
| GET | `/admin/customer-leads/sources` | 来源字典列表 | `200` |
| POST | `/admin/customer-leads/sources` | 新增来源 | `201` |
| POST | `/admin/customer-leads/sources/reorder` | 来源重排 | `204` |
| PATCH | `/admin/customer-leads/sources/{item_id}` | 修改来源 | `200` |
| DELETE | `/admin/customer-leads/sources/{item_id}` | 删除来源 | `204` |
| GET/POST/PATCH/DELETE/reorder | `/admin/customer-leads/tags`（同构 5 条） | 标签字典 CRUD | 同上 |

**出参 `LeadDictItem`**：`id/name/type/enabled/sort`，来源额外返回 `color`（标签 `color` 为 `null`）；`type` 为 `sources` 或 `tags`，供前端复用同一渲染组件。

**入参**：新增 `LeadDictCreate`（`name` 1–64 必填；`color` ≤16 可选；`enabled` 0/1 默认 1；`sort` 默认 0）；修改 `LeadDictUpdate`（同字段均可选，至少提供一个，否则 `422`）；重排 `LeadDictOrder`（`ids` 为期望顺序的 id 数组，1–500 个，服务端按下标从 1 递增写 `sort`）。`item_id` 为正整数 path 参数。

**业务规则**：`name` 同字典内唯一，新增/改名冲突返回 `409`（名称已存在）。删除前统计在用引用：来源按 `name` 匹配有效客源（`customer_lead WHERE source = :name AND deleted_at IS NULL`），标签 JOIN `customer_lead_tag_relation` 统计有效客源；引用数 > 0 返回 `409`（`仍有 N 条有效客源使用该名称，无法删除`）；引用为 0 时物理删除（标签同时清理残留关联行）。

**错误**：`401` 未登录；`403` 无权限；`404` 字典项不存在；`409` 名称冲突或仍被引用；`422` 参数非法。

**与下拉的联动**：`GET /admin/customer-leads/options` 的 `sources` 会合并字典（字典优先、再补历史自由文本，按 `value` 去重）；字典表未建（迁移未执行）时静默跳过，不阻断下拉。

## 择偶要求（新增 2026-10-27）

客源详情抽屉「择偶要求」tab 的读写接口。**复用 C 端 `user_partner_preference` 表与字段口径**，不新建表、不新增迁移。择偶要求挂在线索**入库后生成的账号**（`customer_lead.converted_user_id`）上，因此**仅已入库（`CONVERTED`）线索可编辑**；未入库线索没有可挂载的账号。

### `GET /admin/customer-leads/{lead_id}/preferences`

**基本信息**：读取线索入库账号的择偶要求；成功 `200`；需登录及 `customer_lead.manage`；无请求体。`lead_id` 为正整数 path 参数。

**返回参数 `LeadPreferenceResponse`**：

| 字段 | 类型 | 必返 | 含义 |
|---|---|---|---|
| `lead_id` | int | 是 | 客源线索 ID |
| `converted_user_id` | int\|null | 是 | 入库账号 ID；未入库为 `null` |
| `editable` | bool | 是 | 是否可编辑；未入库为 `false`，前端据此置灰 tab |
| `preference` | object\|null | 否 | 择偶要求；未入库为 `null`。字段同 C 端 `PreferenceResponse`（见 `docs/api/个人资料.md` 第 10 节） |

**返回示例（已入库）**：

```json
{
  "lead_id": 28,
  "converted_user_id": 1001,
  "editable": true,
  "preference": {
    "user_id": 1001, "age_min": 22, "age_max": 30, "height_min": 165, "height_max": 185,
    "education_min": 3, "income_min": 10.0, "marriage_status": 1,
    "preferred_province_code": "440000", "preferred_city_codes": ["440100"],
    "accept_long_distance": false, "accept_cross_province": true,
    "housing_requirement": 1, "smoking_requirement": 0, "drinking_requirement": 0,
    "dating_goal": "倾向结婚", "meeting_pace": "真诚高效", "children_intention": "想要孩子",
    "extra_requirement": null
  }
}
```

**返回示例（未入库）**：`{"lead_id": 28, "converted_user_id": null, "editable": false, "preference": null}`（GET 不报错）。

### `PUT /admin/customer-leads/{lead_id}/preferences`

**基本信息**：写入线索入库账号的择偶要求；成功 `200`（返回同 GET 的 `LeadPreferenceResponse`）；需登录及 `customer_lead.manage`；`Content-Type: application/json`。

**请求体**：复用 C 端 `PreferenceUpdateRequest`，全部字段可选、部分更新。关键字段与校验：`age_min/age_max`（18–100，下限不得大于上限）、`height_min/height_max`（100–250，下限不得大于上限）、`education_min`（1–8）、`income_min`（0–1000000）、`marriage_status`/`housing_requirement`/`smoking_requirement`/`drinking_requirement`（枚举整数）、`preferred_city_codes`（≤20 项）、`dating_goal`/`meeting_pace`/`children_intention`（枚举字符串）、`extra_requirement`（≤255）。非法示例：`{"age_min": 40, "age_max": 30}` 返回 `422`。

**请求体示例**：

```json
{ "age_min": 22, "age_max": 30, "height_min": 165, "height_max": 185, "dating_goal": "倾向结婚" }
```

**使用方法与业务规则**：
- 前置条件：线索必须已入库（有 `converted_user_id`）；未入库返回 `409`（`该客源尚未入库，无法维护择偶要求`）。
- 复用会员自助编辑同一套服务（`update_preferences`），写入会**重算资料完整度并入队画像 revision**，与 C 端 `PUT /users/me/preferences` 同口径。
- 每次成功写入追加一条审计（`action='customer_lead.preference_update'`）。
- 越权/不存在由 `get_lead` 的四档数据范围（D-16）与存在性校验拦截，返回 `404`。

**错误**：`401` 未登录；`403` 无权限；`404` 线索不存在或越权；`409` 线索未入库；`422` 参数非法。

**兼容性**：全部为新增 URL，不改动客源列表、详情、分派、跟进等既有契约；未入库线索读取不报错、仅置灰，前端可安全对任意线索调用 GET。
