# 客源线索 & 自由表单缺失筛选参数（B11，2026-10-24）

> 背景：《后端接口缺失清单》B11「四个列表页筛选参数逐控件缺口审计」列出两处后端真缺筛选。
> 本次把这些前端此前只能靠「塞进 keyword 做 JSON 子串匹配」的脆弱 hack，下沉为服务端正式查询参数。
> 全部为**既有接口的向后兼容参数新增**，不新增路径、不改既有参数语义、不建新表。

## 零、关联的最高优先回归（已在上一轮修复，此处仅登记）

`GET /admin/customer-leads` 曾对所有请求返回 500（MySQL 1241 `Operand should contain 1 column(s)`）。
根因：新增 `gender` 列时，把 `CAST(gender AS SIGNED) AS gender` 误注入 `tags_raw` 标量子查询内部。
现由 `app/services/customer_lead_admin.py::_apply_gender_column` 用 `\bFROM customer_lead\b` 词边界正则
只在外层表引用前补列，子查询体内的 `FROM customer_lead_tag_relation` 因后接 `_` 不构成词边界不会被误匹配。
两处调用点（列表 / 详情）均改走该函数，并带 `if "gender" in columns` 缺列守卫。

## 一、客源线索列表 `GET /admin/customer-leads`

权限：`customer_lead.manage`。数据范围：D-16（`_lead_scope`）。

### 新增查询参数

| 参数 | 类型 | 取值 | 语义 | 落地列 |
|---|---|---|---|---|
| `assigned` | bool | `true` / `false` / 不传 | 分派状态：`true` 只看已分派，`false` 只看**待分派**，不传不过滤 | `customer_lead.matchmaker_id`（IS NOT NULL / IS NULL） |
| `audit_status` | string | `active` / `pending` / `rejected` | 审核状态（`pending` 待核 / `active` 有效 / `rejected` 无效，2026-10-27 新增 `rejected`），非法取值 FastAPI 直接 422 | `customer_lead.audit_status` |
| `stored` | bool | `true` / `false` / 不传 | 入库情况：`true` 已入库（已转平台会员），`false` 未入库 | `customer_lead.converted_user_id`（IS NOT NULL / IS NULL） |

说明：
- 三列均为 `customer_lead` 基础列（`LEAD_SELECT` 已引用），无需迁移。
- 均为可选项，缺省不改变既有查询行为；三者可与已有 29 个参数自由组合。
- 取值一律走命名绑定参数，不拼接 SQL。

## 二、通用内容列表 `GET /admin/content/{domain}`（本项针对 `domain=free_form`）

权限：`platform.config.read`。

### 新增查询参数（仅对 `free_form` 域生效）

| 参数 | 类型 | 取值 | 语义 | JSON 路径 |
|---|---|---|---|---|
| `gender` | string | `1` 男 / `2` 女 | 客户性别，精确匹配 | `$.gender` |
| `landing_id` | string | 落地页 ID | 所属落地页，精确匹配 | `$.landing_id` |
| `source` | string | 来源字典值（如「抖音」） | 客户来源，精确匹配 | `$.source` |

说明：
- 三者走 `JSON_UNQUOTE(JSON_EXTRACT(extra_json, '$.<key>')) = :extra_<key>`，键名来自服务端白名单
  `EXTRA_FILTER_KEYS`，取值走绑定参数；与既有 `type`/`xiangqin_status` 等同机制。
- **域门控**：仿 `good_news_status`/`group_id` 既有范式，`gender`/`landing_id`/`source` 仅在
  `domain=free_form` 时生效；传入其他域时静默忽略（防跨域误筛）。
- 前端应改用这三个正式参数替换此前把 `"gender":".."`、`landing_id":..` 塞进 `keyword` 的子串 hack。
