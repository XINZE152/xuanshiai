# 会员弃海工作台接口（MEMBER-ABANDON-20261109）

会员弃海使用 `member_abandonment` 中 `restored_at IS NULL` 的记录，与资料审核状态独立。以下接口均使用 `/api/v1` 前缀、用户 Bearer 令牌及服务红娘工作台权限；返回 JSON。

## 查询

`GET /matchmaker/workbench/members?member_pool=all&abandoned=true&page=1&page_size=30`

`abandoned=true` 仅返回有效会员弃海记录；`false` 或省略不按弃海筛选。`member_pool=all` 与资料待审的全部会员口径一致；省略时仍限制为当前工作范围。`page` 从 1 开始，`page_size` 为 1–100；可选 `search` 和 `filters` 沿用会员列表契约。不需要请求体。

返回 `items`、`page`、`page_size`、`total`、`has_more` 以及 `abandonment_pool_version=1`。每条会员记录新增 `abandoned`（布尔）和 `abandoned_reason`（字符串或空），`review_status` 保持资料审核状态。客户端在 `abandonment_pool_version` 缺失或小于 1 时不得将审核未通过名单当作弃海名单。

## 弃海

`POST /matchmaker/workbench/members/{member_id}/abandonment`

需要总店超级红娘权限、会员在工作范围内，以及红娘用户关联的有效后台账号。请求 `Content-Type: application/json`，例如 `{"reason":"联系不上"}`；`reason` 为必填非空字符串，最长 500 字。成功返回 HTTP 200 和 `{"member_id":28,"abandoned":true}`。无权限或无关联后台账号返回 403；范围外或会员不存在返回 404；已在弃海池返回 409；原因无效返回 422。重复提交不会创建第二条有效记录。此操作不修改资料审核状态。

## 捞回

`POST /matchmaker/workbench/members/{member_id}/abandonment/pickup`

需要有效的服务红娘工作台身份及关联后台账号；已分派会员须在原工作台弃海捞取范围内，未分派会员可以捞取。不需要请求体。成功返回 HTTP 200 和 `{"member_id":28,"matchmaker_id":1}`，关闭当前有效弃海记录并将会员分派给操作红娘。无关联账号返回 403；会员不在允许范围返回 404；已被捞回或不在弃海池返回 409。捞回不改变资料审核状态。两项写操作均记录审计，客户端应在成功后重新加载列表。
