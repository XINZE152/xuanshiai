# 一期约见接口

接口前缀为 `/api/v1`，需要登录并绑定手机号。约见反馈只返回写入成功，不提供公开反馈查询接口。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/matchmaker/meetings/requests` | 已登录用户 | 已废弃，普通用户不能直接发起约见 |
| `POST` | `/matchmaker/meetings/requests/from-service` | 已认证服务红娘 | 基于红娘服务单发起约见 |
| `GET` | `/matchmaker/meetings/requests/mine` | 已登录用户 | 查询自己发出或收到的申请 |
| `PATCH` | `/matchmaker/meetings/requests/{request_id}` | 申请参与方 | 接受、拒绝、联系或关闭申请 |
| `POST` | `/admin/matchmaker/meetings/requests/{request_id}/schedule` | 超级管理员 | 安排具体约会 |
| `POST` | `/matchmaker/meetings/{meeting_id}/feedback` | 约会参与方 | 提交私有反馈 |
| `POST` | `/matchmaker/workbench/meeting-requests/{request_id}/schedule` | 服务红娘工作台 | 工作台为双方接受的申请安排约见 |
| `PATCH` | `/matchmaker/workbench/meetings/{meeting_id}/status` | 服务红娘工作台 | 工作台流转约见安排状态 |

## 工作台约见排期（2026-09 新增）

### `POST /matchmaker/workbench/meeting-requests/{request_id}/schedule`

服务红娘在工作台为**双方接受的约见申请**（`status = ACCEPTED`）创建约见安排；约见申请必须位于当前红娘服务范围内（SELF 为自己跟进，ORGANIZATION 为同组织）。

- **Headers**：`Authorization: Bearer <用户 JWT>`
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `scheduled_at` | string(datetime) | 是 | 约见时间，必须晚于当前时刻，否则 422 |
| `location` | string(1-128) | 是 | 约见地点，提交前去除首尾空白 |

- **返回**：201 + `WorkspaceMeetingRecordSummary`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int | 约见安排记录 ID |
| `status` | string | 固定为 `SCHEDULED` |
| `scheduled_at` | string(datetime) | 约见时间 |
| `location` | string | 约见地点 |
| `cancel_reason` | string\|null | 取消原因，新建为 null |

- **错误码**：404 申请不存在或不在服务范围；409 申请状态不是 `ACCEPTED`、或该申请已有进行中的安排（`SCHEDULED/REMINDED/CHECKED_IN`）；422 约见时间不是未来时间。

请求示例：

```json
{"scheduled_at": "2026-09-12T15:00:00", "location": "宣誓爱门店会客室"}
```

业务规则：同一申请同时只允许一份进行中的约见安排；安排创建后申请状态保持 `ACCEPTED`；操作写入 `business_audit_log`（action `matchmaker_workspace.meeting.schedule`）。

### `PATCH /matchmaker/workbench/meetings/{meeting_id}/status`

流转服务范围内约见安排的状态。

- **Headers**：`Authorization: Bearer <用户 JWT>`
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 是 | `REMINDED` / `CHECKED_IN` / `COMPLETED` / `CANCELLED` / `NO_SHOW` |
| `cancel_reason` | string(≤200) | 条件 | `CANCELLED` 或 `NO_SHOW` 必填；其他状态不允许携带 |

- **返回**：204 无返回体。
- **错误码**：404 约见安排不存在或不在服务范围；409 已取消（`CANCELLED`）的约见不能恢复；422 取消/爽约未填原因。

业务规则：取消是不可逆终态；流转写入 `business_audit_log`（action `matchmaker_workspace.meeting.record_status`）。

提交申请：

```json
{"target_user_id":23,"note":"希望在门店进行首次沟通"}
```

申请状态：`SUBMITTED`、`CONTACTED`、`ACCEPTED`、`DECLINED`、`CLOSED`。拒绝或关闭必须填写 `reason`。只有 `ACCEPTED` 才能由管理员安排约会。

红娘基于服务单发起约见时，服务状态必须为 `1=服务中` 或 `2=服务完成`；`3=已取消/退款`、服务过期、红娘停用或账号封禁时禁止发起。约见记录必须保留 `service_id` 和 `matchmaker_id`，以便退款、责任和分成追溯。

约会状态：`SCHEDULED`、`REMINDED`、`CHECKED_IN`、`COMPLETED`、`CANCELLED`、`NO_SHOW`。反馈只有约会进入 `CHECKED_IN` 或 `COMPLETED` 后允许提交。
