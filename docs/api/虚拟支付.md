# 20 · 小程序虚拟支付接入说明

> 状态：**代码已落地**（`WECHAT_XPAY_*` + `payOrderCheckout`）  
> 对照官方：[虚拟支付指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

## 为何必须改

微信要求小程序内虚拟商品（会员、解锁功能、社交权益等）全终端接入「虚拟支付」。  
宣誓爱属于「相亲社交」典型场景；会员 / 置顶 / 爆灯均为虚拟权益，不能继续只靠普通 `wx.requestPayment`（JSAPI）。

## 代码改了什么

| 层 | 内容 |
|---|---|
| 后端 | `app/services/payment/xpay.py` 签名与发货；`xpay_notify.py` 推送解密；路由 `/payments/xpay/*`、`virtual-pay-params`、`xpay-confirm` |
| 前端 | `api/payment.uts` 的 `payOrderCheckout`：虚拟支付优先，未开通则回退 JSAPI；VIP/置顶/爆灯已切换 |
| 配置 | `.env.example` 中 `WECHAT_XPAY_*` |

## 你还需要在微信后台做的事（代码无法代劳）

1. MP 开通「虚拟支付」，拿到 **OfferID**、现网/沙箱 **AppKey**
2. 道具管理创建并**发布**（价格单位：分，必须与现网套餐价一致）：
   - 会员：`monthly` / `quarterly` / `yearly`（或用 `WECHAT_XPAY_PRODUCT_MAP_JSON` 映射）
   - 置顶：`boost_1d` / `boost_7d` / `boost_30d`
   - 爆灯：`superlike`
3. 发货推送 URL：`https://<域名>/api/v1/payments/xpay/notify`，配置 Token / EncodingAESKey
4. iOS：配置小程序简称 + 开通 Apple 支付；用户微信 ≥ 8.0.68；最低约 1 元

## 环境变量示例

```bash
WECHAT_XPAY_MODE=real          # 本地可先 mock
WECHAT_XPAY_OFFER_ID=...
WECHAT_XPAY_APP_KEY=...
WECHAT_XPAY_ENV=0
WECHAT_XPAY_PRODUCT_MAP_JSON={"monthly":"vip_monthly","boost_1d":"boost_1d","superlike":"superlike"}
WECHAT_XPAY_PUSH_TOKEN=...
WECHAT_XPAY_PUSH_AES_KEY=...
WECHAT_XPAY_PUSH_ENCRYPT_MODE=aes
```

## 联调顺序

1. `WECHAT_XPAY_MODE=mock`：本地走签名 + `xpay-confirm` 假发货  
2. 安卓真机 + 沙箱/现网小额道具  
3. 现网发货推送验签  
4. iOS Apple 支付（不支持沙箱）

## 未配 ID 时的行为

会员 / 置顶 / 爆灯走 `payOrderCheckout`，**不再回退旧 JSAPI**。

| 配置 | 用户侧表现 |
|---|---|
| `WECHAT_XPAY_MODE=disabled` 或未开 | 提示「虚拟支付尚未开通，暂时无法完成支付」 |
| `real` 但缺 OfferID/AppKey/道具 | 拉起失败或后端 503，支付不成功 |
| `real` 且 ID/道具齐全 | 正常 `requestVirtualPayment` |

旧 `createPrepay` / JSAPI 接口仍保留在仓库，但 C 端付费入口不再调用。
