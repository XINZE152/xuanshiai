# 红娘小程序「分成级别」页面 API

> **归属页面**：红娘小程序 → 红娘管理中心 → 我的分成 → 分成级别（`pagesSub/matchmaker/commission-level`）
> **任务标识**：COMMISSION-LEVEL-20261110
> **后端统一前缀**：`/api/v1/matchmaker/workbench`
> **数据表**：`commission_level`（级别总览，后台「总店红娘 → 分成配置」维护同一份数据）、`matchmaker_profile.commission_level_id`（本人当前级别指派）、`commission_rule`（按消费项目的分成规则版本）
> **同族接口**：`GET /api/v1/matchmaker/workbench/commission-entries`（分成明细）、`GET /api/v1/admin/commission-levels`（后台编辑，见 `docs/api/matchmaker-commission-levels.md`）

---

## 一、通用约定

- **权限口径**：与其余工作台接口一致，使用**普通用户 JWT**（`Authorization: Bearer <access_token>`），服务端再校验 `service_matchmaker` 角色有效；**不需要**红娘后台账号，也不接受后台 Token 旁路。
- **只读投影**：本接口只读，不写任何业务数据；页面版式需要的字段才返回，`commission_level.rate_percent`、`mode`、`platform_extra_pay_mode`、`sort`、`status` 等内部计提配置**不对外暴露**。
- **金额序列化**：所有金额一律返回**字符串**、两位小数（如 `"1000.00"`），前端用 `Number()` 解析展示，避免 JS 精度丢失。
- **不推断原则**：后台未给本人指派分成级别时 `current_level` 返回 `null`；未配置按项目分成规则时 `events` 返回 `[]`。服务端与前端都不得用默认级别或示例数据补齐。

## 三、详细契约

### 3.1 `GET /api/v1/matchmaker/workbench/commission-standards`

**基本信息**

- 用途：为「分成级别」页面提供三块数据——级别总览表（级别名称 / 自动升级条件 / 额外奖励）、本人当前级别（用于身份卡徽标与「您当前的分成标准」标题）、按消费项目的分成标准表（会员消费项目 / 分成金额）。
- 完整 URL：`https://<host>/api/v1/matchmaker/workbench/commission-standards`
- HTTP Method：`GET`
- 是否需要登录：是
- 所需角色/权限：平台用户已登录，且 `service_matchmaker` 角色有效（`user_role` 未过期未禁用）；无需后台权限点
- 请求 Content-Type：无请求体
- 响应 Content-Type：`application/json`
- 成功状态码：`200`

**请求参数**

无 path 参数、无 query 参数、无 body 参数。

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 校验规则 | 业务含义 |
|---|---|---|---|---|---|---|
| Authorization | header | string | 是 | 无 | `Bearer <access_token>`，Token 由 `POST /api/v1/auth/login` 系列接口签发，未过期 | 当前登录用户；服务端据此解析红娘身份与准入 |

- 合法示例：`Authorization: Bearer eyJhbGciOiJIUzI1NiIs...`
- 非法示例：`Authorization: Bearer `（空 Token）→ `401`；使用红娘后台账号 Token → 同样只按该账号对应的平台用户判定，无后台旁路。

**请求体示例**

```
GET /api/v1/matchmaker/workbench/commission-standards HTTP/1.1
Host: xhztest.xyz
Authorization: Bearer <access_token>
```

无请求体。非法示例：`GET /api/v1/matchmaker/workbench/commission-standards?page=abc`——本接口不接收任何查询参数，多余的 `page/page_size/keyword` 等参数会被忽略，不参与筛选。

**返回参数**

| 字段名 | 类型 | 必返 | 空值含义 | 枚举含义 | 业务含义 | 示例值 |
|---|---|---|---|---|---|---|
| levels | array\<object\> | 是 | 不会为 null；后台把 4 行级别全部停用时为 `[]` | — | 级别总览表，按后台 `sort, id` 升序，只含 `status = 1` 的生效行 | 见返回示例 |
| levels[].code | string(≤32) | 是 | 不为空 | 种子值 `junior` / `intermediate` / `senior` / `partner`（后台可新增其他 code，前端不得按枚举写死文案） | 级别编码，用于与 `current_level.code` 对齐 | `"intermediate"` |
| levels[].name | string(≤64) | 是 | 不为空 | — | 级别名称，直接展示 | `"中级分成"` |
| levels[].promotion_condition | string(≤128) \| null | 否 | `null` 表示后台未填写升级条件，前端显示 `--` | — | 自动升级条件原文描述 | `"牵线成功累计>=10次"` |
| levels[].platform_extra_amount | string | 是 | 不为空，零为 `"0.00"` | — | 达到该级别时平台的额外奖励（元），两位小数字符串 | `"1000.00"` |
| current_level | object \| null | 是 | `null` 表示后台尚未给本人指派分成级别；前端显示 `--` 占位，**不得**按 `levels[0]` 当默认级别 | — | 当前登录红娘本人的分成级别，字段结构与 `levels[]` 完全一致 | 见返回示例 |
| current_level.code / name / promotion_condition / platform_extra_amount | 同上 | — | 同上 | 同上 | 同上 | `"intermediate"` / `"中级分成"` |
| events | array\<object\> | 是 | 不会为 null；后台未配置按项目分成规则时为 `[]`，页面显示明确空状态 | — | 按消费项目的分成标准，取 `beneficiary_type = 'service_matchmaker'` 且 `status = 1` 的规则，**同名多版本只保留 `version` 最大的一条**，按 `priority, id` 升序 | 见返回示例 |
| events[].name | string(≤128) | 是 | 不为空 | — | 会员消费项目 / 分成事件名称 | `"资料审核费"` |
| events[].mode | string | 是 | 不为空 | `fixed`（按固定金额分成）/ `rate`（按消费金额比例计提） | 该条标准的计算方式，决定金额与比例哪个有值 | `"fixed"` |
| events[].amount | string \| null | 否 | `mode = 'rate'` 时为 `null` | — | `fixed` 模式的固定分成金额（元），两位小数字符串 | `"2.00"` |
| events[].rate_percent | string \| null | 否 | `mode = 'fixed'` 时为 `null` | — | `rate` 模式的计提比例（百分数的数值部分），两位小数字符串，展示需自行补 `%` | `"15.00"` |

**返回示例**

成功（后台已配置 4 行级别、已指派本人级别、已配置按项目规则）：

```json
{
  "levels": [
    { "code": "junior", "name": "初级分成", "promotion_condition": "默认", "platform_extra_amount": "5.00" },
    { "code": "intermediate", "name": "中级分成", "promotion_condition": "牵线成功累计>=10次", "platform_extra_amount": "1000.00" },
    { "code": "senior", "name": "高级分成", "promotion_condition": "牵线成功累计>=100次", "platform_extra_amount": "1000.00" },
    { "code": "partner", "name": "合伙分成", "promotion_condition": "牵线成功累计>=300次", "platform_extra_amount": "5000.00" }
  ],
  "current_level": { "code": "intermediate", "name": "中级分成", "promotion_condition": "牵线成功累计>=10次", "platform_extra_amount": "1000.00" },
  "events": [
    { "name": "资料审核费", "mode": "fixed", "amount": "2.00", "rate_percent": null },
    { "name": "季度会员开通", "mode": "rate", "amount": null, "rate_percent": "15.00" }
  ]

```

无数据（后台未指派本人级别、未配置按项目规则；级别行仍在）：

```json
{
  "levels": [
    { "code": "junior", "name": "初级分成", "promotion_condition": "默认", "platform_extra_amount": "5.00" }

  "events": []

```

本接口不分页，无 `items/page/page_size/total/has_more`；`levels` 与 `events` 一次返回全量生效行。

**使用方法与业务规则**

- **前置条件**：用户已登录且 `service_matchmaker` 角色有效。红娘申请未审核通过或角色已失效时返回 `403`，不返回半成品数据。本期不以支付作为准入条件。
- **调用顺序**：页面进入时先由小程序路由参数无参调用本接口取级别与标准；身份卡所需的名称/头像/签名走既有接口 `GET /api/v1/matchmaker/workbench/identity` 与 `GET /api/v1/matchmaker/workbench/homepage`，本接口不重复回带用户资料。分成流水走 `GET /api/v1/matchmaker/workbench/commission-entries`。
- **幂等与防重**：纯读接口，天然幂等；重复请求返回当前配置快照，不产生任何写入、不扣次数、不影响资金账本。
- **频率/额度限制**：服务端未对本接口设置额外限流，沿用全局中间件；页面每次进入取一次即可，不做轮询。
- **状态流转**：本接口不改变任何状态。级别变更只发生在后台 `PUT /api/v1/admin/commission-levels/{level_id}`；本人级别变更只发生在后台红娘编辑（`matchmaker_profile.commission_level_id`）。
- **边界场景**：
  - 后台把某行级别 `status` 置 0：该行从 `levels` 消失；若本人档案正指向这一行，`current_level` 同样返回 `null`（级别 JOIN 只认 `status = 1` 的生效行），前端把它显示为 `--`，不得回退成 `levels[0]`。
  - `promotion_condition` 为空字符串：服务端归一化为 `null`。
  - 同名规则存在多个 `version`：只返回最大版本一条，历史版本不对 C 端暴露。
  - `commission_rule.mode = 'rate'` 的行没有 `fixed_amount`：`amount` 为 `null`，前端按 `mode` 决定展示「N 元」还是「N%」。
- **前端处理建议**：`levels` 或 `events` 请求失败时保留可重试入口并显示接口错误文案；不得用本地示例数据补齐表格。远端环境尚未部署本接口时，小程序侧的接口能力清单会直接返回「远端暂未开放此功能」，页面应显示未开放说明而不是空表。

**错误**

| HTTP 状态码 | 触发条件 | 错误响应示例 | 前端处理建议 |
|---|---|---|---|
| 401 | 未携带或携带无效 Token | `{"detail": "Could not validate credentials"}` | 引导重新登录，不重试同一 Token |
| 403 | `service_matchmaker` 角色无效或未激活 | `{"detail": "服务红娘申请审核通过并激活后可进入管理中心"}` | 原样展示 `detail`，引导去申请成为红娘 |
| 422 | 误传了被声明为查询参数的字段且类型不符（本接口无参数，正常调用不会出现） | `{"detail": [{"loc": ["query", "page"], "msg": "...", "type": "..."}]}` | 视为调用方 bug，移除多余参数 |
| 500 | 服务端异常（配置表不可用等） | `{"detail": "Internal Server Error"}` | 提供「重新加载」，不要把故障当作空数据展示 |

**兼容性**

- 本次为**新增接口**，无历史客户端依赖，向后兼容。
- `levels[]` 与 `current_level` 字段结构一致，新增字段只可能追加，不改变既有字段语义。
- 明确**不返回** `rate_percent`（级别计提比例）、`mode`（级别分成方式）、`platform_extra_pay_mode`（额外奖励发放方式）等后台配置字段；若页面未来需要展示，需另行评审并扩展契约，不得由前端反推。
