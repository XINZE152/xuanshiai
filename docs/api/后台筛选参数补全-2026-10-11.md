## 1. 新增 `GET /admin/finance/credit-records`（积分明细列表）

### 基本信息

- 用途：分页查询积分账户流水，对应前端「财务管理 → 积分明细」页（`/system-credit-history`）。
- 完整 URL：`/api/v1/admin/finance/credit-records`
- Method：`GET`；需登录；权限 `finance.read`（缺权限 403）。
- 成功状态码：`200`。

### 请求参数

| 参数 | 位置 | 类型 | 必填 | 默认值 | 校验/枚举 | 业务含义 |
|---|---|---|---|---|---|---|
| `page` | query | int | 否 | 1 | `>=1` | 页码 |
| `page_size` | query | int | 否 | 20 | `1-100` | 每页条数 |
| `member_scope` | query | string | 否 | — | `verified` / `xiangqin` / `xiangqin_female` / `xiangqin_male` / `online_vip` | 会员范围：实名认证 / 相亲会员 / 相亲女会员 / 相亲男会员 / 线上VIP |
| `action_source` | query | string | 否 | — | 当前仅 `admin` | 操作来源；`admin` = 后台人工发放或扣减 |
| `category` | query | string | 否 | — | `recharge` / `gift_exchange` / `gift_received` / `gift_sent` | 积分类别：积分充值 / 礼品兑换 / 收礼物奖励 / 送礼物 |
| `start_date` | query | string | 否 | — | 长度 ≤10；**空字符串视为不筛选** | 起始日期（含当日 00:00:00） |
| `end_date` | query | string | 否 | — | 长度 ≤10；**空字符串视为不筛选** | 结束日期（含当日 23:59:59，实现为 `< end+1 天`） |
| `keyword` | query | string | 否 | — | 长度 1-64 | 会员昵称模糊匹配，或纯数字时按会员 ID 精确匹配 |

- 合法示例：`?page=1&page_size=20&member_scope=xiangqin_female&category=recharge&start_date=2026-10-01&end_date=2026-10-11&keyword=138`
- 非法示例：`?member_scope=vip`（不在枚举内 → 422）、`?page_size=101`（>100 → 422）
- 兼容说明：日期参数不传、或传空字符串（`?start_date=`）一律视为"不筛选"，**不会触发 422**。这是 2026-09-12 `fix(M9): finance.orders 日期 query 422` 确立的全库约定，本页所有日期参数一律照此执行。

### 返回参数

`CreditRecordPage`

| 字段 | 类型 | 必返 | 业务含义 |
|---|---|---|---|
| `items` | array | 是 | 当前页流水，无数据时为空数组 `[]` |
| `page` | int | 是 | 当前页码 |
| `page_size` | int | 是 | 每页条数 |
| `total` | int | 是 | 符合条件的总条数 |
| `has_more` | bool | 是 | `page * page_size < total` |

`items[]`（`CreditRecordItem`）

| 字段 | 类型 | 必返 | 空值含义 | 枚举/业务含义 |
|---|---|---|---|---|
| `id` | int | 是 | — | `account_ledger.id` |
| `user_id` | int | 是 | — | 会员 `users.id` |
| `nickname` | string\|null | 是 | 会员未设置昵称 | 会员昵称 |
| `avatar` | string\|null | 是 | 未上传头像 | 头像 URL |
| `phone` | string\|null | 是 | 未绑定手机 | 手机号，**按调用者敏感权限等级脱敏后下发** |
| `direction` | string | 是 | — | `CREDIT` 入账 / `DEBIT` 消耗 |
| `amount` | number | 是 | — | 变动积分数，正数（方向看 `direction`） |
| `state` | string | 是 | — | `PENDING` / `AVAILABLE` / `REVERSED` |
| `source_type` | string | 是 | — | 流水来源类型，如 `admin_grant` |
| `action_source` | string | 是 | — | 文案：`管理员操作`（`source_type=admin_grant`）或 `系统` |
| `category` | string\|null | 是 | 该来源未归类 | 积分类别编码，取值同请求 `category` 枚举 |
| `operator_id` | int\|null | 是 | 非人工操作为 `null` | 操作人 `users.id`（仅管理员操作有值） |
| `created_at` | string(date-time) | 是 | — | 流水发生时间 |

### 返回示例

```json
{
  "items": [
    {
      "id": 9102,
      "user_id": 88,
      "nickname": "小雅",
      "avatar": "https://cdn.example.com/a.png",
      "phone": "138****8000",
      "direction": "CREDIT",
      "amount": 100,
      "state": "AVAILABLE",
      "source_type": "admin_grant",
      "action_source": "管理员操作",
      "category": "recharge",
      "operator_id": 3,
      "created_at": "2026-10-11T09:12:33"
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "has_more": false
}
```

空数据：`{"items": [], "page": 1, "page_size": 20, "total": 0, "has_more": false}`

### 使用方法与业务规则

- 前置条件：登录且具 `finance.read`。
- 数据范围：`account_ledger.account_type='user'`，并按当前后台账号的数据范围（ALL/SELF/STORE/ORGANIZATION）**失败关闭**式收敛，越权数据不会出现在结果里。
- `member_scope` 各取值的 SQL 语义：`verified` → `users.is_real_name=1`；`xiangqin` → `user_privacy.match_status IN (1,2)`；`xiangqin_female/male` 在此基础上叠加 `gender`；`online_vip` → 存在有效期内 `user_membership`。
- `category` 通过 `account_ledger.source_type` 反查归类；`recharge` 映射到 `admin_grant`，礼品类映射到 `gift_exchange/gift_received/gift_sent`。
- 幂等：纯查询，可重复调用。
- 边界：`keyword` 为纯数字时**同时**按会员 ID 精确匹配（`u.id = keyword`），非数字时 ID 侧用 `-1` 兜底，不会误命中。

### 错误

| HTTP | 触发条件 | 前端处理 |
|---|---|---|
| 401 | 未登录 / token 失效 | 跳登录 |
| 403 | 缺 `finance.read` | 提示无权限并隐藏入口 |
| 422 | `page_size>100`、日期参数长度 >10、枚举越界 | 展示字段级错误，重置筛选条件 |
| 500 | 未捕获异常 | 提示联系管理员 |

## 4. 变更 `GET /admin/offline-vips`（线下VIP，对应 `/love-user-vip-underline`）

| 参数 | 类型 | 校验/枚举 | 业务含义 |
|---|---|---|---|
| `service_status` | string | `active` / `expired` / `no_refund_risk` | 服务状态：服务期内 / 已过期 / 无退费风险。**与 `progress`（服务进度）是两套维度，独立参数，不合并进 `progress`** |
| `sort_by` | string | `member_last_paid` / `member_history_paid` / `monthly_sales` / `yearly_sales` / `monthly_champion` | 统计排序：会员最近一次付费 / 会员历史付费 / 月度销售额 / 年度销售额 / 每月销冠 |
| `column_sort` | string | `sign_date` / `package` / `progress` / `last_follow` / `amount` / `matchmaker` / `id` | 表头列排序：点表头时传，**优先于 `sort_by`**；不传时沿用原统计维度排序 |

排序键同样是服务端白名单内的固定 SQL 片段（含销售额统计所需的 JOIN），不接受任意列名。
`column_sort` 与 `sort_by` 是两套维度：前者对应表格列点击，后者对应「销冠/销售额」类统计视图；
同时传时以 `column_sort` 为准（用户的即时点击意图）。

> 实现注意：`last_follow` 的时间来自 `member_follow_up` 子查询，`offline_vip` 表本身没有跟进时间列，
> 排序片段必须重复该子查询，不能写 `v.last_follow_at`（该列不存在，会直接 500）。

**示例**：`GET /api/v1/admin/offline-vips?service_status=no_refund_risk&sort_by=monthly_sales`
**示例（表头排序）**：`GET /api/v1/admin/offline-vips?column_sort=amount`
**非法示例**：`?sort_by=amount`（枚举越界 → 422）、`?column_sort=nope`（→ 422）

## 5. 变更 `GET /admin/content/{domain}`（通用内容项，覆盖 `/free-pay` `/gift-exchange` 等页）

| 参数 | 类型 | 校验/枚举 | 业务含义 |
|---|---|---|---|
| `type` | string | ≤32 | 内容类型，取自 `extra.type`：`page` 单页 / `landing` 引导页 / `form` 自由表单 |
| `qrcode_type` | string | ≤32 | 二维码类型，取自 `extra.qrcode_type`：`h5` 普通H5二维码 / `follow` 引导关注公众号 |
| `xiangqin_status` | string | ≤16 | 相亲状态，取自 `extra.xiangqin_status`：1公开相亲 2委托红娘 3完全私密 4停止相亲 5已经脱单 |
| `search_type` | string | ≤32 | `keyword` 的匹配目标，**按域生效**：`free_pay_order`、`gift_exchange` 支持 `nickname` 会员昵称 / `phone` 手机号 / `order_no` 订单号 |
| `good_news_status` | string | ≤32 | `good_news` 域按 `extra.status` 筛选喜讯状态 |
| `matchmaker_id` | string | ≤20 | `good_news` 域按 `extra.matchmaker_id` 筛选服务红娘 |
| `group_id` | string | ≤20 | `group_signup` 域按 `extra.group_id` 筛选社群 |
| `pay` | string | ≤16 | `group_signup` 域按 `extra.pay` 筛选支付状态 |
| `nick` | string | ≤64 | `group_signup` 域按 `extra.nick` 模糊匹配昵称 |

- 这三个字段按 `admin_content_item` 的设计存放在 `extra_json`，筛选走 `JSON_UNQUOTE(JSON_EXTRACT(extra_json, '$.<key>')) = :extra_<key>`；键名来自服务端白名单 `EXTRA_FILTER_KEYS`，取值走绑定参数。
- `search_type` 在本域未定义时，退回 `title / subtitle / extra_json` 全字段模糊匹配（历史行为）。
- `good_news_status` 与 `matchmaker_id` 仅对 `good_news` 有业务意义，其他域传入时不会扩大查询范围。
- `group_id`、`pay` 与 `nick` 仅对 `group_signup` 有业务意义；昵称使用模糊匹配，其余字段使用精确匹配。

**示例**：`GET /api/v1/admin/content/free_pay_order?type=form&search_type=order_no&keyword=FP20261011`
**非法示例**：`GET /api/v1/admin/content/unknown_domain`（域不在白名单 → 404）

前端实际调用的是 `POST`，后端原本只注册了 `PATCH`。以下 4 个端点改为 `PATCH` 与 `POST` 挂到**同一个 handler**（`api_route(methods=["PATCH","POST"])`），body、幂等结果、权限完全一致，不复制实现：

|---|---|

| `/admin/community/paper-planes/{plane_id}/moderation` | 管理员 |

**兼容性**：`PATCH` 保留，老客户端不受影响；`POST` 为新增方法，属非破坏性扩展。

## 9. 分成事件种子数据
