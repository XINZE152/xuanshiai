# 工作台会员服务跟进图片

任务标识：WORKSPACE-FOLLOWUP-IMAGES-20261111。

管理员端与工作台共用 `member_follow_up`、`member_follow_up.images` 及私有文件；工作台使用普通用户 JWT，必须是已开通工作台的红娘。图片内容仅供红娘查看。原有跟进的列表接口响应 `items[].images` 返回工作台图片读取路径，不返回存储路径；无图片返回空数组。已有字段及分页语义保持不变。

## 权限变更（FOLLOWUP-SCOPE-20261112）

此前列表、创建和图片接口统一要求会员符合工作范围，总店超级红娘无法对未归属会员操作，门店超级红娘可访问同门店其他红娘的会员。现在总店超级红娘可读取并提交所有未软删除会员的跟进；其他服务红娘（含门店超级红娘）仅可访问当前有生效归属、且归属红娘是本人的会员。上述规则同时适用于文字列表、创建、图片读取及上传；不存在、已删除或无权访问的会员返回 404。图片上传仍要求记录由当前账号通过工作台创建，不改变该限制。管理员端接口及数据表不变。

## 会员跟进列表与提交

- `GET /api/v1/matchmaker/workbench/members/{member_id}/follow-ups?page=1&page_size=20`：用户 Bearer 令牌，无请求体；`member_id` 为正整数，`page` 为 1–1000，`page_size` 为 1–100。成功返回 `{"items":[],"page":1,"page_size":20,"total":0,"has_more":false}`。每条记录含 `id`、`user_id`、`method`、`content`、可空的 `next_follow_at`、`created_at` 和图片路径数组 `images`。
- `POST /api/v1/matchmaker/workbench/members/{member_id}/follow-ups`：用户 Bearer 令牌，JSON 请求体，例如 `{"method":"PHONE","content":"已联系会员","next_follow_at":null}`。`method` 必填，取 `PHONE`、`WECHAT`、`VISIT`、`OTHER`；`content` 必填，长度 1–2000；`next_follow_at` 可为日期时间或 null。成功返回 201 和新建记录；无效参数返回 422。提交会写入共享跟进表和审计记录，重复请求会创建新记录。
- 两接口未登录返回 401，未开通工作台返回 403，会员不存在或无权访问返回 404。先创建文字跟进，再上传该记录的图片。

## 上传图片

`POST /api/v1/matchmaker/workbench/members/{member_id}/follow-ups/{follow_up_id}/images`，`Authorization: Bearer <用户令牌>`，`Content-Type: multipart/form-data`，成功返回 204，无响应体。

| 参数 | 位置及类型 | 必填 | 规则与说明 |
| --- | --- | --- | --- |
| member_id | path integer | 是 | 正整数，会员 ID，例如 20；0 非法 |
| follow_up_id | path integer | 是 | 正整数，必须是该会员且由当前用户通过工作台创建的跟进，例如 10 |
| file | form file | 是 | JPG、JPEG 或 PNG，单张不超过 5 MiB、不超过 2500 万像素 |
| upload_key | form string | 是 | 1–64 个字母、数字、下划线或连字符；每张图片固定且不同，重试使用原值，例如 `0`；空串非法 |

示例：先调用 `POST /api/v1/matchmaker/workbench/members/20/follow-ups` 创建记录，然后将 `file=@photo.jpg`、`upload_key=0` 作为表单上传至 `/api/v1/matchmaker/workbench/members/20/follow-ups/10/images`。同一记录最多九张；每张单独上传。相同记录和 upload_key 的重试为幂等操作。文字记录先保存，某张失败后用同一个 key 重试；已成功上传的图片仍保留。管理员端查询同一记录时可看到图片。

## 读取图片

`GET /api/v1/matchmaker/workbench/members/{member_id}/follow-ups/{follow_up_id}/images/{index}`，`Authorization: Bearer <用户令牌>`，无请求体，成功返回 200 `image/webp` 二进制和 `Cache-Control: private, no-store`。

| 参数 | 位置及类型 | 必填 | 规则与说明 |
| --- | --- | --- | --- |
| member_id | path integer | 是 | 正整数，例如 20 |
| follow_up_id | path integer | 是 | 正整数，例如 10 |
| index | path integer | 是 | 图片在列表中的零基位置，0–8；9 非法 |

例如先通过 `GET /api/v1/matchmaker/workbench/members/20/follow-ups?page=1&page_size=20` 获取 `items[0].images`，再以用户令牌下载 `/api/v1/matchmaker/workbench/members/20/follow-ups/10/images/0`。无图片时列表为 `"images": []`，无读取请求。图片内容需要使用带请求头的下载接口获取，不可直接以无认证的图片地址访问。

## 错误

401：令牌缺失或过期；403：账号无工作台权限；404：会员不在范围内、记录不可修改或图片不存在；413：图片超出大小或像素限制；415：图片格式无效；422：参数错误或图片超过九张。错误响应通常为 `{"detail":"图片最多9张"}`。失败时应展示原因；网络故障或 5xx 可使用同一 upload_key 重试，不得换 key 后盲目重传。
