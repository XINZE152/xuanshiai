# 一期组织、门店和归属接口

接口前缀为 `/api/v1`。除推广触点和加入团队接口外，组织配置接口要求超级管理员权限。所有接口使用 JSON，认证头为 `Authorization: Bearer <access_token>`。

## 门店和资源

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/organizations/stores` | 超级管理员 | 创建门店 |
| `GET` | `/organizations/stores` | 超级管理员 | 查询门店 |
| `GET` | `/organizations/stores/{store_id}` | 超级管理员 | 查询门店详情 |
| `POST` | `/organizations/stores/{store_id}/members` | 超级管理员 | 添加店长或门店红娘 |
| `POST` | `/organizations/assignments` | 超级管理员 | 分派会员门店和服务红娘 |

创建门店请求：

```json
{"code":"shanghai-01","name":"上海门店","display_name":"上海直营店","region_code":"310000","auto_redirect":false}
```

`code` 只能使用字母、数字、下划线和短横线；一个门店最多一个有效 `store_manager`。资源分派会结束同一会员的旧有效归属，历史记录保留。

## 推广和合伙团队

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/promotions/touches` | 已登录推广红娘 | 创建自己的推广码 |
| `POST` | `/promotions/attributions` | 已登录用户 | 确认自己的首次推广归属 |
| `POST` | `/partners/teams` | 超级管理员 | 创建合伙团队 |
| `POST` | `/partners/memberships` | 已登录推广红娘 | 加入一个合伙团队 |

推广归属只允许一个有效归属；重复确认返回 `409`。扫描合伙人码只应先记录触点，成为推广红娘并确认加入团队后才成为有效团队成员。

错误：`401` 未登录，`403` 业务身份或权限不足，`404` 组织/推广码/团队不存在，`409` 重复成员、重复归属或店长冲突，`422` 参数不合法。

## 合伙人中心与推广红娘中心增强（2026-09 二期新增）

以下接口挂在 `/matchmaker` 前缀下（如 `/api/v1/matchmaker/...`），使用普通用户 JWT，按 `user_role` 校验合伙人/推广红娘身份。

### 快照字段扩展

`GET /matchmaker/partner-center` 响应新增：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `profile.phone` | string\|null | 合伙人手机号 |
| `profile.wechat_bound` | bool | 是否已绑定微信（依据 `users.wechat_bound_at`） |
| `profile.register_at` | datetime\|null | 注册时间 |
| `team_members[].effective_count` | int | 该推广红娘名下审核通过的有效会员数 |
| `registration_rewards[]` | array | 团队注册奖励展示明细（审核通过 1 元/人，展示口径） |
| `level` | object | `level`（初级合伙/中级合伙/战略合伙）、`effective_member_count`、`next_level`、`member_gap` |

`GET /matchmaker/promoter-center` 响应 `profile` 新增：`phone`、`wechat_bound`、`register_at`、`team_name`、`team_status`（`NONE` 未申请 / `PENDING` 待合伙人确认 / `ACTIVE` 已加入）、`level`（初级/推广大师/推广大使/推广天使）、`next_level`、`member_gap`。

### 入团申请（邀请码 + 合伙人确认）

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/matchmaker/promoter-center/team-requests` | 推广红娘 | 凭团队邀请码提交入团申请 |
| `DELETE` | `/matchmaker/promoter-center/team-requests/{request_id}` | 推广红娘（本人） | 撤回待确认申请 |
| `GET` | `/matchmaker/partner-center/join-requests?status=PENDING` | 合伙人 | 查询团队入团申请 |
| `PATCH` | `/matchmaker/partner-center/join-requests/{request_id}` | 合伙人 | 审批（APPROVED/REJECTED） |

提交申请请求体：

```json
{"invite_code": "AbC123xyz"}
```

`invite_code` 必须是合伙人团队邀请码（`promotion_touch` 中 `promoter_id IS NULL AND partner_team_id` 非空的记录）。返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int | 申请 ID |
| `team_id` / `team_name` | int / string | 目标团队 |
| `promoter_id` / `promoter_nickname` / `promoter_avatar` | - | 申请人信息（仅合伙人查询时用于展示） |
| `status` | string | `PENDING` / `APPROVED` / `REJECTED` / `CANCELLED` |
| `created_at` / `reviewed_at` / `reject_reason` | - | 时间与拒绝原因 |

审批请求体：`{"status": "APPROVED"}` 或 `{"status": "REJECTED", "reason": "原因"}`（拒绝必填 reason，≤200 字）。

业务规则：一人只能有一条有效 `partner_membership`；存在 `PENDING` 申请时不能重复申请；通过审批即写入 `partner_membership` 并使本人其余 `PENDING` 申请失效；已加入团队的申请人提交返回 `409`。全部操作写入 `business_audit_log`（`matchmaker_workspace.partner_join.*`）。

错误：`403` 身份不符，`404` 邀请码/申请不存在，`409` 重复申请、团队关闭或已加入其他团队，`422` 参数不合法。

### 团队邀请小程序码

`POST /matchmaker/partner-center/qrcode`（合伙人）：返回 `{"code": "<邀请码>", "image": "data:image/png;base64,..."}`。服务端调用微信 `getwxacodeunlimit`，scene 为 `team={team_id}&code={邀请码}`；未配置 `wechat_app_id/secret` 时返回 `503 微信小程序码服务未配置`。无可用邀请码时自动生成一份。
