# 兴趣标签字典（后台 CRUD）

## 通用约定

所有接口前缀为 `/api/v1`，需要 `Authorization: Bearer <access-token>`，且后台账号必须具有 `interest_tag.manage` 或 `*` 权限。目录为全局配置型数据，**不做数据范围收敛**（不随门店/组织归属过滤）。

兴趣标签目录是 C 端资料页 `personal_tags` / `tag-options` 使用的标签来源，此前是后端写死的常量，2026-10-27 起落库为 `interest_tag_category`（分类）与 `interest_tag`（标签）两张表，由本组接口维护。每次写库成功后服务端刷新进程内缓存，`GET /api/v1/profile/tag-options` 与标签校验即时反映新目录（单进程部署下无跨进程陈旧问题）。

建表与初始数据由 `migrations/interest_tag_catalog/` 播种（17 分类 / 323 标签，与原常量一致）。迁移未执行或表为空时，运行时会回退到内置常量目录，C 端行为不变。

## 端点总览

| 方法 | 路径 | 用途 | 成功状态 |
|---|---|---|---|
| GET | `/admin/interest-tags/categories` | 分类列表（按 sort 升序） | `200` |
| POST | `/admin/interest-tags/categories` | 新增分类 | `201` |
| POST | `/admin/interest-tags/categories/reorder` | 分类重排 | `204` |
| PATCH | `/admin/interest-tags/categories/{item_id}` | 修改分类 | `200` |
| DELETE | `/admin/interest-tags/categories/{item_id}` | 删除分类 | `204` |
| GET | `/admin/interest-tags/tags` | 标签列表（可按 `category_key` 过滤） | `200` |
| POST | `/admin/interest-tags/tags` | 新增标签 | `201` |
| POST | `/admin/interest-tags/tags/reorder` | 标签重排 | `204` |
| PATCH | `/admin/interest-tags/tags/{item_id}` | 修改标签 | `200` |
| DELETE | `/admin/interest-tags/tags/{item_id}` | 删除标签 | `204` |

`item_id` 均为正整数 path 参数。`reorder` 静态段先于 `/{item_id}` 动态段注册。

## 分类

**出参 `TagCategoryItem`**：`id / key / label / enabled(0|1) / sort`。`key` 是前端与存储引用的稳定标识（提交 `tag_selections`、`custom_tag_categories` 时使用），**创建后不可修改**。

**入参**：
- 新增 `TagCategoryCreate`：`key`（必填，1–64，仅小写字母/数字/下划线，正则 `^[a-z0-9_]{1,64}$`）、`label`（必填 1–64）、`enabled`（0/1，默认 1）、`sort`（默认 0）。
- 修改 `TagCategoryUpdate`：`label / enabled / sort` 均可选，至少提供一个，否则 `422`。不支持改 `key`。
- 重排 `TagOrder`：`ids` 为期望从前到后的 id 数组（1–1000 个），服务端按下标从 1 递增写 `sort`。

**业务规则**：`key` 全局唯一，新增冲突返回 `409`（分类 key 已存在）。删除前检查其下是否仍有标签：存在则返回 `409`（该分类下仍有 N 个标签，请先删除或迁移标签），无标签才物理删除。

## 标签

**出参 `TagItem`**：`id / category_key / name / enabled(0|1) / sort`。

**入参**：
- 新增 `TagCreate`：`category_key`（必填，须为已存在的分类 key）、`name`（必填 1–64）、`enabled`（0/1，默认 1）、`sort`（默认 0）。
- 修改 `TagUpdate`：`name / enabled / sort` 均可选，至少提供一个，否则 `422`。**不支持换分类**（避免历史 `tag_selections` 归属漂移）。
- 重排 `TagOrder`：同分类重排，按下标写 `sort`。

`GET /admin/interest-tags/tags?category_key=food` 只返回该分类的标签；省略 `category_key` 返回全部（按分类、sort 排序）。

**业务规则**：
- 同一 `category_key` 下 `name` 唯一，新增/改名冲突返回 `409`（该分类下标签名称已存在）。
- 新增时 `category_key` 不存在返回 `422`（所属分类不存在）。
- 删除前统计在用引用：扫描 `user_profile` 的 `interest_tags` / `personality_tags` / `tags` JSON 列，命中该标签名（`JSON_CONTAINS`）即计数；引用数 > 0 返回 `409`（仍有 N 位用户在用该标签，无法删除）；引用为 0 时物理删除。

## 错误码

`401` 未登录；`403` 无 `interest_tag.manage` 权限；`404` 分类/标签不存在；`409` key 或名称冲突、分类下仍有标签、标签仍被引用；`422` 参数非法或所属分类不存在。

## 缓存与生效

- 服务端进程内缓存承载当前目录；启动时（`app/main.py` lifespan）从两表加载，后台每次写库成功后自动刷新。
- 表缺失或未播种（分类为空）时缓存回退内置常量目录，`reload` 不抛错，保证迁移未执行的环境（含本地/测试）行为不变。
- 停用（`enabled=0`）的分类或标签不进入缓存、不出现在 `tag-options`，也不参与标签校验；数据行仍在，可重新启用。
