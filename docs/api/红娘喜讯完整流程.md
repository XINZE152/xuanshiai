# 红娘喜讯、锦旗与祝福

任务：GOOD-NEWS-20261104。以下完整 URL 均为 `{后端地址}/api/v1` 加表中路径；本地地址 `http://127.0.0.1:8000`，既定远端 `https://xhztest.xyz`。

## 登录、权限与公共约定

所有接口使用 `Authorization: Bearer <用户令牌>`，要求已启用红娘工作台身份。JSON 请求/响应为 `application/json`；上传图片使用 multipart/form-data。

普通红娘只能访问自己归属的喜讯、收到的锦旗；旧锦旗缺少受赠 ID 时回退匹配工作台姓名。总店可查看已审核内容和自己名下的待审内容。跨范围的详情、祝福读取和写入统一返回 404，不能通过不同接口绕过可见范围。新锦旗以当前红娘 ID 为受赠人，客户端不能指定其他受赠 ID；改名不会丢失新记录。

所有提交先写入已有 `admin_content_item` 的待审行（status=2）；后台喜讯/锦旗管理审核为 status=1 后才可送祝福。状态值中的审核 status 与 extra.status 的喜讯阶段是不同字段。新表单要求主动确认取得会员同意；历史反馈客户端未传 consent_confirmed 的请求暂兼容，但 public 默认为 false，需管理员审核展示设置，不代表已获得同意。

## 接口一览

| --- | --- | --- | --- |
| GET | `/matchmaker/workbench/good-news?stage=恋爱生活&page=1&page_size=20` | 200 | 喜讯分类列表，stage 留空为全部 |

| POST | `/matchmaker/workbench/good-news` | 201 | 提交喜讯，待审核 |
| POST | `/matchmaker/workbench/good-news/photo` | 201 | 上传照片或生成的锦旗图片 |
| GET | `/matchmaker/workbench/good-news/pennants?page=1&page_size=20` | 200 | 锦旗列表 |

GET 无请求体。item_id 为 path 正整数，合法 7，非法 0；分页 query 参数 page 默认 1、范围 1–1000，page_size 默认 20、范围 1–100；stage 最长 20，七个内置分类为牵手成功、恋爱生活、已见父母、已订婚、已领证、已办婚礼、婚后生活。锦旗单独使用 pennants 接口，不作为喜讯提交阶段。

### 提交喜讯

请求示例：`POST http://127.0.0.1:8000/api/v1/matchmaker/workbench/good-news`，携带上述 Authorization 与 Content-Type Headers。

```json
{"stage":"恋爱生活","feedback_name":"李先生","partner_name":"林女士","meet_duration":"5","content":"双方正在认真了解，感谢红娘的服务。","images":["/storage/uploads/good-news/photo-a.webp"],"consent_confirmed":true,"client_request_id":"good-news-20261104-unique-1"}
```

| Body 字段 | 类型 | 必填/默认 | 校验与含义 |
| --- | --- | --- | --- |
| stage | string | 必填 | 内置七阶段之一；非法“锦旗飘扬”返回 422 |
| feedback_name | string | 默认空 | 反馈人称呼，最多 40 字；新前端要求填写 |
| partner_name | string | 必填 | 对方称呼，去空白后非空、最多 40 字 |
| meet_duration | string | 默认空 | 最多 20 字，数字按月解释，展示时补“个月” |
| content | string | 默认空 | 最多 1000 字，按纯文本展示 |
| images | string[] | 默认 [] | 最多 9 个已上传图片 URL，不自动代表隐私处理或已获展示授权 |
| consent_confirmed | boolean/null | 新表单 true；历史默认 null | 明确 false 返回 422；新表单必须勾选后提交 |
| client_request_id | string/null | 新表单必传；历史默认 null | 8–64 字，同一登录人/同一域重复 key 返回原记录，不重复建档 |

成功 `{"id":7,"pending_review":true}`。id 为新记录整数编号；pending_review 为 true 表示待审，重复请求若该记录已通过审核则为 false。非法示例：partner_name 为纯空格、stage 为“未知”、consent_confirmed 为 false 均返回 422。

### 提交锦旗

请求示例：`POST http://127.0.0.1:8000/api/v1/matchmaker/workbench/good-news/pennants`。

```json
{"giver":"李先生","left_words":"感谢红娘牵线","right_words":"珍惜美好相遇","date_text":"二零二六年十一月","image_url":"/storage/uploads/good-news/photo-pennant.webp","consent_confirmed":true,"client_request_id":"pennant-20261104-unique-1"}
```

| Body 字段 | 类型 | 必填/默认 | 校验与含义 |
| --- | --- | --- | --- |
| giver | string | 必填 | 赠送人，1–40 字，不能全空格 |
| left_words | string | 必填 | 左感谢语，1–8 字，不能全空格 |
| right_words | string | 必填 | 右感谢语，1–8 字，不能全空格 |
| date_text | string | 默认空 | 最多 24 字，显示在锦旗上的日期文案 |
| image_url | string/null | 默认 null | 最多 1024 字，若提供须为 `/storage/uploads/good-news/` 上传路径；不传时客户端按文字展示锦旗 |
| consent_confirmed | boolean | 必填 true | false 为 422 |
| client_request_id | string | 必填 | 8–64 字，与喜讯的幂等 key 分域 |

成功同上返回 id、pending_review。受赠人、受赠 ID、制作方、提交人取服务端当前身份，不信任客户端指定归属。非法示例 image_url=`https://other.test/a.png`、giver 为纯空格返回 422。生成预览和保存相册是客户端操作，不等于提交锦旗成功；只有本接口成功才显示“已提交待审核”。

### 图片上传

`POST http://127.0.0.1:8000/api/v1/matchmaker/workbench/good-news/photo`：multipart body 字段 `file` 必填，文件大小上限 5 MiB，使用现有图片解码、尺寸处理和 WebP 输出流程；非法图片拒绝，不直接存任意文件。返回 `{"url":"/storage/uploads/good-news/photo-xxx.webp","thumbnail_url":"/storage/uploads/good-news/photo-xxx-thumb.webp","size":12345}`。url/thumbnail_url 为可入库相对 URL，前端展示时拼对应环境后端地址；size 为输出文件字节数。

## 列表和详情返回

喜讯/锦旗分页统一：items 数组、page 当前页、page_size 页大小、total 范围内总数、has_more 是否还有下一页、workflow_version=2。本期前端不展示栏目实时总数，但仍使用分页游标。空列表 `{"items":[],"page":1,"page_size":20,"total":0,"has_more":false,"workflow_version":2}`。

喜讯详情对象与 items 中的单项一致：

| 字段 | 类型/必返 | 含义与空值 |
| --- | --- | --- |
| id / stage | int / string，必返 | 编号、阶段 |
| from_user_id / to_user_id | int/null，必返 | 后台已关联的双方会员编号；空表示仅手填称呼，不提供跳转身份 |
| from_name / to_name | string，必返 | 双方称呼；历史缺失可能为占位串，前端不展示未知一侧 |
| from_avatar / to_avatar | string/null，必返 | 已关联会员头像，可空 |
| matchmaker_name | string，必返 | 服务红娘展示名 |
| meet_duration | string，必返 | 相识时间显示文案，可空 |
| images | string[]，必返 | 图片 URL，空数组表示无图片 |
| content / blessing | string，必返 | 纯文本正文、后台历史祝福文案，可空 |
| blessing_count | int，必返 | 历史祝福数加新写入祝福数 |
| public / pending_review | boolean，必返 | 后台展示标记、是否待审；分享入口仅对非待审且允许公开的喜讯展示 |
| created_at | ISO datetime/null，必返 | 反馈时间，历史可能为空 |

示例：`{"id":7,"stage":"恋爱生活","from_user_id":null,"to_user_id":null,"from_name":"李先生","to_name":"林女士","from_avatar":null,"to_avatar":null,"matchmaker_name":"服务红娘","meet_duration":"5个月","images":[],"content":"双方正在认真了解","blessing":"","blessing_count":1,"public":true,"pending_review":false,"created_at":"2026-11-04T10:00:00"}`。

锦旗单项字段：id(int)、maker(string 制作方)、giver(string 赠送人)、target(string 受赠人)、words(string 合并感谢语)、image_url(string/null 完整锦旗图)、created_at(datetime/null 赠送记录时间)、left_words/right_words(string 左右感谢语)、date_text(string 印刷日期)、target_user_id(int/null 受赠红娘 ID，旧记录可空)、pending_review(bool 待审)。这些字段均返回；空字符串表示历史未填写，image_url 为空可使用文字锦旗版式。

## 送祝福与祝福记录

请求示例 `POST http://127.0.0.1:8000/api/v1/matchmaker/workbench/good-news/7/blessings`，Body `{"message":"愿你们彼此珍惜，一起经历更多美好。"}`。message 为必填 string，去空白后 1–100 字；纯空格、101 字返回 422。无需客户端提交计数或发送者 ID。

成功示例 `{"blessing_count":1,"blessed":true,"created":true}`。blessing_count 为写入后的总数，blessed 表示当前人已祝福，created 表示本次是否新增。相同人重复/并发发送返回 created=false，不覆盖第一条祝福、不重复加数；待审喜讯返回 409。目标行锁、去重、祝福记录、计数和审计在同一事务中完成。

GET 祝福记录无请求体，query 参数同上。响应示例 `{"items":[{"id":8,"nickname":"会员昵称","avatar":null,"message":"送上祝福","created_at":"2026-11-04T10:00:00"}],"total":1,"page":1,"has_more":false,"blessed":true}`。items 子项均必返，avatar 可空；total 为有详细记录的新祝福条数，可能小于含历史总数的 blessing_count。旧计数没有历史明细时展示“暂无可查看的祝福记录”，不编造记录。空状态 items=[]，has_more=false。

## 错误、部署与验证

| HTTP | 条件 | 前端处理 |
| --- | --- | --- |
| 401 | 登录失效 | 重新登录目标环境 |
| 403 | 工作台未启用 | 显示无权限说明 |
| 404 | 目标不存在/越权，或旧服务缺少新路由 | 详情显示不可用；旧服务提示该能力未开放，不伪装写入成功 |
| 409 | 待审喜讯送祝福 | 提示等待审核 |
| 422 | 参数、阶段、同意确认、图片路径无效 | 保留表单提示修正 |
| 5xx/网络错误 | 服务或网络异常 | 保留内容允许重试，不降级成 Mock 成功 |

标准错误示例 `{"detail":"喜讯不存在或不在服务范围"}`（404）。数据库结构未变，无新增迁移；喜讯/锦旗沿用原域，新增祝福明细使用已有 admin_content_item 的 good_news_blessing 域，JSON 保存关联编号。旧后台管理继续审核 good_news、good_news_pennant；祝福域不作为内容运营列表开放。

先部署本后端并重启，再发布配套前端；本地验证不能代表远端已部署。单测覆盖权限、待审限制、同意确认、去重及失败事务；隔离 MySQL 覆盖反馈/锦旗幂等、并发祝福只写一次、计数和记录一致、改名归属。相关测试已登记 backend-ci.yml。
