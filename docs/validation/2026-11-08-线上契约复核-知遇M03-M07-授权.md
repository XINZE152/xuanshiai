## 6. 错误码在哪一层

对 v2 定稿 §2 的 12 个错误码（`AI_CONSENT_REQUIRED`、`AI_POLICY_DENIED`、`AI_INPUT_INVALID`、`INVALID_CANDIDATE_CURSOR`、`AI_QUOTA_EXCEEDED`、`DRAFT_VERSION_CONFLICT`、`RESULT_STALE`、`TASK_IDEMPOTENCY_CONFLICT`、`SEARCH_DRAFT_NOT_FOUND`、`SEARCH_SNAPSHOT_NOT_FOUND`、`AI_FEATURE_DISABLED`、`AI_TEMPORARILY_UNAVAILABLE`）：

- 在**线上和本地的 OpenAPI 里都检索不到**（逐 schema、逐 path 检索，两边命中集合相同）。
- OpenAPI 里出现的相关枚举只有 `AiCapabilitiesResponse`（含 `AI_FEATURE_DISABLED`）与 `ProfileDraftPatchRequest`（含 `DRAFT_VERSION_CONFLICT`），以及 3 条 path 描述文本里的 `AI_INPUT_INVALID`。
- M03 的 `422` 在 OpenAPI 中是通用校验错误壳，**不含业务码**。

结论：**错误码的权威契约来源是 [docs/api/AI搜索.md](AI搜索.md)，不是 `/openapi.json`**。v2 定稿 §6「线上 `/openapi.json` 与 `docs/api/AI搜索.md` 一致」这一条验收项，实际只能验到路径/参数/字段层；错误码需另按文档层比对。前端不要用 `openapi.json` 建错误码映射表。

同理，`Idempotency-Key` 的 `8-128 位 [A-Za-z0-9._:-]` 约束在两边的 schema 里都**没有** `minLength`/`maxLength`/`pattern`（线上 `required=false`），它由服务端代码校验并在不合规时返回 `400 AI_INPUT_INVALID`（`app/api/routes/ai_consents.py:50-60`）。文档层已写明该约束，OpenAPI 层不体现——比对时不要误判为「线上缺校验」。
