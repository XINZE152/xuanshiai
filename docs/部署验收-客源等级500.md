# 客源等级 500 修复部署与验收

任务：LEAD-500-20261103。

## 原因和修复

同一个 customer_lead 表，管理端的 intention_level 已允许 1–7，红娘工作台此前只允许 1–3。
已有等级 4 的行在 `_lead_from_row` 构造 WorkspaceLead 时触发 ValidationError，使整个列表返回 500。
修复统一工作台录入、编辑、跟进、列表返回值为 1–7，保留存量等级和原有数据权限。
没有数据库迁移，不需要修改、清空或复制任何数据库数据，不依赖本地后端。

## 发布

1. 合并包含本修复的后端 PR 到正式仓库 `redspider-ai/xuanshiai` 的部署分支。
   仅拉取尚未合并该 PR 的 main 不会获得修复。
2. 在远端当前后端代码目录使用既有部署流程拉取部署分支，保留服务器现有 `.env`、数据库及密钥。
3. 使用服务器原有 systemd、进程管理器或容器发布流程重启所有 API worker/实例。
   本仓没有服务器的服务名、部署目录或容器名，不应套用猜测的重启命令。
4. 小程序联调配置保持 `USE_LOCAL_BACKEND = false`，请求地址应为 `https://xhztest.xyz/api/v1/...`。
   不需要启动本地后端；本修复为后端变更，小程序无需为此重新发版。

## 只读远端验收

在任意有 Python 3 的维护终端执行：

```bash
python scripts/verify_remote_workspace_leads.py --base-url https://xhztest.xyz
```

首先检查远端 `/openapi.json` 的五个模型均接受 1–7，未部署新代码时退出 1。
仅契约通过但没有登录凭据会退出 2，不能算功能验收通过。

通过维护者自己的安全方式将**原故障红娘账号**的 access token 设置为环境变量
`XSA_SMOKE_ACCESS_TOKEN` 后，再执行同一命令。不要将 token 提交到仓库、写入文档或发送给其他人。
脚本只发送 GET，不写库，不打印 token、联系方式或响应正文；返回 0 表示契约及有数据的列表请求均通过。
401/403 为账号或凭据问题，500 表示仍未修复或另有异常；有多个实例时须确保都运行新版本。

最终在小程序使用原账号进入客源页，确认列表显示、原等级 4 的记录可见；编辑其他字段保存后等级仍为 4。
验收不能用空列表、其他账号、Mock 或本地服务结果替代。
