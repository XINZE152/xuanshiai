## 墨相师实时语音 v2（SenseAudio）P0 收尾（2026-09-12）

状态：后端全链路（realtime 包 + 路由 v2 + 元数据迁移/历史）已实现并提交 `feat/senseaudio-realtime`；路由级真实端到端 PASS。两项供应商侧缺陷与真机验证未闭环，启用实时分支前必须完成。

- **供应商缺陷 1（P0，已实验定案：客户端不可修）**：`update`（instructions-only）被以非致命 `invalid_tts_speed`（语速 0.0）整条忽略。2026-09-12 归因实验：补未文档化字段 `tts_speed=1.0` 可让报错消失，但行为验证证明 instructions 更新仍不生效（update 前后回复行为完全一致）；`speed`/`speech_rate` 无效；`commit` 变体会完全破坏 VAD 定稿。结论：供应商 update 管道丢弃 instructions 更新，唯一可靠路径是"上下文变化即轮转上游"（已实现），并附实验数据提工单。
- **供应商缺陷 2（P0，已排除我方变量）**：回复音频流中断流（`sami 52000016 AudioTTSIdleTimeoutError`）——文本增量全量到达后 TTS 音频播 8~11s 断粮，~40s 空闲被杀并漏发 `turn.done`。归因实验（`scripts/probe_senseaudio_variants.py`）：去尾静音/发 commit 均不能改善（commit 反而 3/3 无定稿），断流签名与上行策略无关，坐实为供应商 LLM→TTS 流水线问题。控制器两级兜底（10s 完成宽限 + fatal 轮转）保证产品可用；完整轮次成功率待供应商修复后复测 `scripts/e2e_moxiang_realtime_route.py`。
