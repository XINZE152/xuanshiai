## 0. 背景与目标

担心 AI 服务 API 到期 / 配置过期后，前端入口照常展示、用户点进去才报 503。目标：

1. 前端 **71 个页面**（pages.json 实测：7 主包 + 64 分包）都有对应显示开关；开关关闭时入口隐藏、直达拦截。
2. AI 能力具备**运行时紧急关停**通道（免重启，分钟级生效），应对 API 到期。
3. 开关由管理端配置，C 端匿名可拉取（游客态也要能隐藏入口）。

### BE-02 页面注册表与生效值计算（P1）

- 新文件：`app/services/page_switches.py`。
- 内容：
  - `PAGE_REGISTRY: dict[path, module]`，71 个路径与 pages.json 一一对应（含 5 个 tab 页标记 `is_tab=True`）。
  - `effective_page_switches(db) -> dict`：读 `platform_page_switches`，生效值 = `modules[模块] AND pages[路径]`；缺失键一律回退 True（fail-open）。**生效值只在后端算，前端不复制与/或逻辑**（与 capabilities 同一设计哲学，避免两处漂移）。
  - 30 秒进程内 TTL 缓存，避免每请求打 DB；DB 异常保留上次缓存。
- 模块归属建议：ai（search、my-portrait-master/result/archive、my-ai-avatar）、emotion_lab（1 页）、community（社区 10 页）、paper_plane（纸飞机 4 页）、matchmaker（13 页）、membership（vip、unlock-history、my-date-service 等）、parent（2 页）、profile_tools（其余 profileExtra）、chat（chat/detail）、system（tab 其余 4 页、auth、settings、security、help、about、userExtra 等）。system 模块关闭仅影响入口与直达，**登录/注册页建议注册表标记 `allow_disable=False`**，防止把用户锁死在 App 外。

2. 管理端 `PATCH /admin/configs/ai_runtime` 置 `master_kill=true` 演练：≤30 秒后 `/ai/capabilities` 全 false、AI 接口 503 `AI_FEATURE_DISABLED`；改回 false 恢复。演练在测试服先做。
3. 前端版本发布（含守卫代码）→ 提审 → 上线。
4. 端到端演练：关 `ai` 模块 → 真机确认入口消失/直达被拦 → 恢复。
5. 回滚：后端开关全 fail-open，PATCH 回默认即回滚；前端守卫在接口不可用时 fail-open，不阻塞回滚。

## 4. 风险与边界

- 微信约束（2026-11-17 修订）：本项目 tabBar `custom:true` 自绘，tab **条目可隐藏**；但 pages.json 静态注册不变，tabBar.list 须保留，switchTab/分享/扫码直达仍需页内占位兜底。"隐藏"= 入口+直达拦截，页面仍在包内。
- 开关生效依赖前端先发布一次守卫版本；此前仅后端行为受控。
- 多 worker 部署下 kill 生效时延 = TTL（≤30 秒），非瞬时。
- API 到期本身不会自动触发开关（本方案是手动应急通道）；"provider 健康检查自动关断"不在本期，可另立任务。
- `online_match_enabled/membership_enabled/matchmaker_enabled` 后端未消费为存量缺口，本任务只下发不扩权执行，避免范围蔓延。
