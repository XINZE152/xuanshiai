# 媒体存储访问盘点与迁移方案

> 本文是访问风险盘点，不改变历史 URL、文件位置、数据库字段或部署契约。任何私有化迁移、URL 过渡、旧文件搬迁和线上发布都需要另行专项授权。
>
> **2026-09-27 更新**：§5 兼容止损方案的第 1 步已以「响应层重签 + 挂载层签名验签」方式实施（follow-up/audio/cert/admin 四类），详见 §5.1；公开资料媒体与社区媒体保持静态公开，§6 完整迁移仍未实施。

## 1. 当前事实

`app/main.py:145-146` 将整个 `settings.upload_dir` 直接挂载为 `/storage/uploads` 的 `StaticFiles`，该挂载没有认证依赖。因而同一目录下的文件具有相同的 HTTP 传输边界：知道 URL 即可匿名 `GET`，与生成 URL 的业务接口是否需要登录无关。

风险复现脚本 `scripts/reproduce_upload_exposure.py` 使用 `TemporaryDirectory`、`create_app()` 和 `TestClient`，不连接数据库、不读取本机上传目录。它分别写入跟进图片、跟进录音和普通资料图片哨兵文件，再以无 Cookie/Authorization 的请求验证当前行为；脚本预期三者均返回 `200`，仅供手动风险证据，不属于默认 pytest 集。
（2026-09-27 更新：脚本哨兵已扩展为跟进图片、跟进录音、用户语音、普通资料图片四类，预期分别为 `403/403/403/200`，并在文首标注止损已实施；详见 §5.1。）

## 3. 资源分类与权限矩阵

| 类别 | 当前生成位置/URL | 当前消费方 | 应有读取角色 | 当前匿名结果 | 历史 URL/缓存影响 |
| --- | --- | --- | --- | --- | --- |
| 公开资料媒体 | `/{user_id}/avatar-*`、`photo-*`、`background-*`、`video-*`；`/storage/uploads/{user_id}/...` | 公开资料、本人资料页 | 已审核且已发布的公开媒体可匿名读取；未审核/撤回对象不应继续公开 | 静态挂载会按路径返回，绕过 `review_status` | 公开 URL 可能被客户端、CDN、微信缓存；撤回需考虑缓存失效 |
| 社区图片/视频及缩略图 | `/{user_id}/community/*` | 帖子、纸飞机、社区媒体审核/展示 | 应按 `community_media` 状态、过期时间和可见范围控制；未绑定/未审核对象不应公开 | 静态挂载会按路径返回，数据库状态不参与文件下载 | URL 存在于媒体记录和客户端响应，直接下线会影响帖子/纸飞机 |
| 纸飞机/聊天语音 | `/{user_id}/audio/*` | 语音消息、纸飞机 | 已认证用户且通过会话/内容归属校验的参与者 | 静态挂载允许匿名读取 | 语音 URL 可能已写入消息或纸飞机数据；需要兼容期和缓存控制 |
| 红娘后台跟进附件 | `/{member_id}/follow-up-img-*`、`follow-up-voice-*` | 红娘 CRM 跟进详情 | 具备 `matchmaker.member.read` 且对目标会员有组织/业务归属的后台角色 | 当前 `200`，不需要后台凭据 | 历史跟进记录直接保存 URL；迁移需要逐条映射和回滚清单 |
| 用户认证材料 | 用户目录下 `education-cert-*`、`house-cert-*`、`single-pledge-*` 或认证字段引用的 URL | 用户本人认证页、平台审核后台 | 本人查看自身状态；具备认证审核权限的后台角色；其他用户禁止 | 当前静态挂载按路径可读 | 认证材料具有高敏感性；旧 URL 不能直接公开兼容 |
| AI/系统语音及后台资源 | `voice/tts`、`tts`、`admin` 等上传根目录子路径 | 对应任务或后台页面 | 按任务、账号和短期有效期授权；不应作为公共静态资源 | 需按具体路径核验，静态挂载原则上可读 | 可能被日志、任务结果或后台响应引用；需单独盘点 TTL 与缓存 |

### 权限结论

- 必须匿名失败：红娘跟进附件、认证材料、纸飞机/聊天语音、未审核或已撤回的社区/资料媒体、AI/后台临时资源。
- 可匿名读取的最小范围：仅明确标记为已审核、已发布的公开资料媒体；这不等于整个 `upload_dir` 可静态公开。
- 普通用户、红娘后台、认证审核后台和资源所属用户必须使用不同的授权判断，不能仅凭用户 ID 或 URL 前缀推断权限。
- 本矩阵是隔离环境设计基线，不代表当前线上已满足这些边界。

## 4. 隔离访问证据

`scripts/reproduce_upload_exposure.py` 使用 `TemporaryDirectory` 写入三类哨兵文件，随后以无 Cookie/Authorization 的 `TestClient` 请求验证。2026 年 9 月 25 日结果：

- 跟进图片：`200`，内容完全匹配。
- 跟进录音：`200`，内容完全匹配。
- 普通资料图片：`200`，内容完全匹配。
- 路径穿越请求：返回 `400` 或 `404`，未观察到目录外文件读取。
- 不存在文件：`404`。

这些结果证明路径规范化本身没有扩大到目录外，但不能抵消“知道合法路径即可匿名读取”的权限问题。当前脚本没有伪造后台身份或数据库归属，因此合法授权读取、普通用户越权和跨后台角色越权仍需在隔离数据库/服务环境补测。

**2026-09-27 复测**：私有类哨兵（跟进图片/跟进录音/用户语音）匿名直连均为 `403`，公开资料图片仍为 `200` 且内容一致，路径穿越与不存在文件保持 `404`；带有效签名的请求可正常读取（签名/验签回归见 `tests/test_media_access_follow_up.py`、`tests/test_media_access_audio.py`、`tests/test_media_access_cert_admin.py`）。

## 5. 兼容止损方案（第 1 步已于 2026-09-27 实施）

### 5.1 已实施范围与方式

- **已纳管四类私有媒体**：跟进附件（`{member_id}/follow-up-img-*`、`follow-up-voice-*`）、用户语音（`{user_id}/audio/*`）、认证材料（`{user_id}/education-cert-*`、`house-cert-*`、`single-pledge-*`）、后台资源（`admin/*`）。
- **实施方式**：`app/services/media_access.py` 类别化注册表 + `app/main.py` `_ProtectedStorageFiles` 挂载层验签。私有类响应在返回给查看者前按其身份重签短期 URL（HMAC-SHA256，签名消息含类别/查看者类型/相对路径/过期/查看者/修订六元组，TTL 300 秒）；挂载层验签并按查看者类型查询状态（user→`users.status`、admin→`matchmaker_admin_account.status`），**数据库不可用 → 503 fail-closed，账号停用/不存在 → 403，全链路无 `401`**。
- **零数据迁移**：数据库仍存原始 URL，签名仅在响应层生成；提交边界（纸飞机、会话消息、聊天消息）剥离客户端回传的签名参数后入库。
- **观测**：未签名请求命中私有前缀时输出 WARNING（类别 + 存储相对路径，不含 query 与内容），为 §6 完整迁移提供证据。
- **既有 TTS 机制零改动**：`tts/`、`voice/tts/` 仍走 `voice/audio_access.py` 原链路（挂载层委托），Windows 全栈反斜杠路径的潜伏旁路已在门面归一化修复。

### 5.2 残余风险与限制（如实声明）

- **签名 URL 在 TTL 300 秒内对任何持有者有效**：挂载层是匿名静态服务，无法认证请求者身份；泄露窗口靠 TTL 收窄，以及账号停用/隐私修订变更时的挂载层状态校验兜底。本止损**不等于防转发/防共享**。
- **公开资料媒体与社区媒体仍走静态公开**（§3 矩阵中"公开资料媒体""社区图片/视频"两类）：其审核状态联动与分区搬迁属 §6 完整迁移范围，未在本方向实施。
- **管理端语音回放限制**：后台消息审计视图（`app/services/message_admin.py`）的语音 `media_url` 不重签（管理员后台账号与 `users` 表语义不匹配，强行重签会产生永久 403 的假签名，且放宽钩子到「users 或 admin 任一有效」会引入 id 空间重叠吊销漏洞）；管理端直连语音为 `403`，需要听证走既有运维手段；如需支持须以独立管理端钩子类别专项设计。
- **后台资源缩略图**：`common_upload` 响应仅签发主图 URL，缩略图（`{name}-thumb.webp`）直连 `403`；前端仅消费响应 URL 时不受影响。
- **chat_voice**：`purpose=chat_voice` 上传的语音不存在独立的 chat 语音专项面——它经文档化的 `type=3` 消息 API 服务端落库并已随第 2 步纳管：纸飞机会话消息（`community.py` send 剥离签名后存原始 URL，list/send 响应按会话成员重签）与社交聊天消息（`social.py` send 剥离后存原始 URL，`_message` 按当前查看者重签）；语音文件读取与上述两类消息的语音共用同一套签名验签链路，无额外残余风险。
- **前端交互模式**：私有媒体 URL 过期（>5 分钟）后播放/加载会 `403`，前端应重新调用对应业务接口获取新 URL，不得自行拼接或重放旧 URL。

### 5.3 原方案条目（未实施部分）

1. 保留现有公开资料 URL 作为兼容入口，但停止将整个 `upload_dir` 挂载为无鉴权静态根目录。——已部分实施（私有类验签，公开类与社区媒体仍静态公开）。
2. 新增私有媒体读取路由：按资源类型、资源 ID、登录身份、组织/后台权限、会话参与关系和撤销/过期状态做归属校验，再用 `FileResponse` 或流式响应返回。——以挂载层签名验签替代实施（深度归属校验保留在签发端既有 RBAC/会话校验，避免静态挂载层复制完整 RBAC 造成双源漂移）。
3. 新写入的跟进附件、语音、认证材料和临时系统资源进入私有目录；数据库保存资源类别、对象键或等价可校验元数据。——未实施（仍按原始目录布局，DB 存原始 URL）。
4. 公开资料只有在审核状态和发布状态均满足时才生成公开对象或公开 URL；审核撤回时由发布层撤销公开对象。——未实施。
5. 对旧私有 URL 先建立观测和兼容策略，再按专项授权选择鉴权读取、明确拒绝或短期重定向；不直接删文件。——观测已实施（见 5.1）；兼容策略与后续处置待专项授权。

## 6. 完整迁移方案（未实施）

1. 建立 `public-profile`、`community-moderated`、`follow-up-private`、`voice-private`、`certification-private`、`system-private` 分区。
2. 生成资源清单：来源表、记录 ID、旧 URL、实际路径、SHA-256、媒体类型、归属用户/组织、目标对象键和可见性。
3. 在隔离存储复制并校验哈希、大小、MIME 和缩略图关系；先切读后切写，保留旧路径只读观察期。
4. 为历史 URL 定义过渡期限、缓存失效、客户端兼容、失败重试、重复执行和回滚点；迁移脚本必须幂等且禁止删除源文件作为第一步。
5. 逐类验收匿名、本人、同角色、跨角色、撤销授权、过期对象和公开媒体，再安排受控环境切换。

本方向完成了 §5.1 的兼容止损（四类私有媒体签名验签）；§5.3 未实施条目与上述 §6 完整迁移仍需专项授权后另行排期。
