# 系统管理 · 后端执行逐项审计报告

> 审计日期：2026-09-09
> 审计范围：「系统管理」菜单下本次接线的纯配置页面（系统配置 7 Tab、广告管理、外呼平台、短信签名、短信通知配置）对应的 `sys_*` 配置域，在后端运行时是否真的被消费。
> 结论先行：**全部 `sys_*` 配置域当前仅"能存、能读回、有审计"，后端没有任何业务运行时代码读取它们**——它们属于"管理端配置占位"。要让某项真正影响运行时，需在对应入口补消费点（见第五节）。

---

## 一、后端消费配置的唯一入口与现状

后端读取 `admin_config_snapshot` 的运行时函数只有：

```python
# app/services/admin_config.py:232
async def get_runtime_value(db, namespace, key, fallback): ...
```

全后端调用点此前已确认仅有 2 个文件、8 处，全部属于 `platform_permissions` 配额键（discovery/community 每日浏览/申请/爆灯/纸飞机限额）。

本次新增 10 个配置域（`sys_site`、`sys_access`、`sys_storage`、`sys_payment`、`sys_watermark`、`sys_posters`、`sys_region`、`sys_ads`、`sys_outbound`、`sys_sms`）在 `app/services/admin_config.py` 中定义默认结构，但**全后端无任何其它代码引用这些 namespace**（grep 确认仅定义处出现）。即：

- 没有 `get_runtime_value(db, "sys_*", ...)` 调用；
- 没有对 `admin_config_snapshot` 的其它直接查询；
- 没有把这些配置域暴露给用户端/客户端/第三方服务商的公共接口。

## 二、逐页面审计

### 1. 系统配置（`/system-setting-basic`）

| Tab | 配置域 | 后端是否执行 |
| --- | --- | --- |
| 基本信息 | `sys_site` | ❌ 无消费。经营主体/域名/备案/客服/协议/隐私/LGO 等无任何后端读取；用户协议与隐私政策文本也未出现在用户端注册/协议接口 |
| 注册访问 | `sys_access` | ❌ 无消费。后端注册/浏览/登录逻辑读的是 `settings` 与业务开关，不读本域（`browse_enabled`、`register_enabled`、IP 限制均未接入对应鉴权/访问控制） |
| 文件存储 | `sys_storage` | ❌ 无消费。图片上传 `/admin/common/upload` 与用户上传写的是本地 `storage/uploads`（settings.upload_dir），不读七牛配置 |
| 支付配置 | `sys_payment` | ❌ 无消费。后端支付 `wechat_payment_mode` 由 `app/core/config.py` 的 settings 控制（默认 mock），不读本域商户参数 |
| 图片水印 | `sys_watermark` | ❌ 无消费。上传服务未做水印叠加 |
| 海报配置 | `sys_posters` | ❌ 无消费。海报由客户端/前端各自实现 |
| 自定义区域 | `sys_region` | ❌ 无消费。省市区数据另有 `regions` 路由/表，与此域无关 |

### 2. 广告管理（`/system-setting-adconfig`）→ `sys_ads`
❌ **无消费**。后端已有 `config_banner` 是**社区模块**专用（`community_admin.py` 在用），与本页 H5/小程序广告位（`sys_ads`）无关；H5/小程序首页广告位没有对应后端下发接口。

### 3. 外呼平台（`/outbound-call-platform`）→ `sys_outbound`
❌ **无消费**。后端不存在外呼/坐席/呼叫模块（grep 仅命中 `member_records_admin.py` 的业务表字段，非外呼服务）。本配置域仅为将来接入第三方外呼（建讯/厚朴/云客）预留。

### 4. 短信签名（`/sms-signature`）→ `sys_sms.signature`
❌ **无消费**。后端短信实现 `services/sms/providers.py` 只有 `disabled`/`mock` 两种 provider，读的是 `settings.sms_provider` 环境变量；签名值不参与任何发送流程（短信验证码发送在 `routes/auth.py`，模板为固定文案）。

### 5. 短信通知配置（`/sms-notices`）→ `sys_sms.notices`
❌ **无消费**。60+ 通知场景开关仅存储于此；后端没有基于这些场景枚举发送业务短信的调度代码。真实业务通知（若实现）需逐场景在此域读取开关/模板。

## 四、根因

1. **本组为"系统级第三方/部署参数"**：七牛、微信支付、外呼、短信等服务本质是外部集成，当前后端以 `settings` 环境变量 + mock 实现为主（`wechat_payment_mode=mock`、`sms_provider=disabled/mock`），并未为这些外部能力建立可切换配置的数据链路。
2. **配置域是"管理面存档"**：本次新增的 `sys_*` 域按平台配置同款机制存储，仅后台可读写；既无业务入口消费，也无用户端/服务商对接代码读取。
3. **部分页面其实已有真实数据源**：广告位（社区 `config_banner`）、区域（`regions` 表/路由）、账号（`matchmaker_admin_account`）各自存在，但与本页静态 UI 语义并不对应，需逐项确认归属后才能决定接哪套真实表。

## 五、要让"配置真正驱动后端"需要的动作（按优先级）

| 优先级 | 配置域 | 需要做的事 |
| --- | --- | --- |
| P0 | `sys_access` | 在用户端浏览鉴权/注册接口加开关判断（browse/register）；在登录流程接入登录安全增强与 IP 黑/白名单中间件；短信验证码开关接入注册发码逻辑 |
| P1 | `sys_storage` | 统一上传服务改为可配置存储后端：settings 或 `sys_storage` 选择本地/七牛，并把密钥从配置域脱敏读取（接入密钥管理系统） |
| P1 | `sys_payment` | 把支付网关从 settings 静态值改为读取 `sys_payment`（启用/商户参数/证书），`/payments` 创建订单与回调验签均按配置选择 provider |
| P1 | `sys_sms` | 短信服务按 `sys_sms` 读取签名/开关，并补"业务通知场景 → 模板/开关 → 发送"的调度；验证码发送模板改用配置中的签名 |
| P1 | `sys_outbound` / 外呼记录 | 若上外呼业务，需在后端新增外呼服务商客户端（按配置取 provider/账号/呼叫中心地址）与坐席、呼叫记录表，页面记录区才有真实数据 |
| P2 | `sys_watermark` / `sys_posters` | 上传服务加图片水印处理；海报图若后端生成则读取配置 |
| P2 | `sys_ads` | 如需 H5/小程序广告位由服务端下发，新增公开配置接口返回广告位与图片 URL |
| P2 | `sys_region` | 区域数据管理与 `regions` 真实数据源打通（或移除占位） |
| P3 | `sys_site` | 协议/隐私文案、LOGO、客服信息若要对用户端展示，新增公开站点信息接口供客户端拉取 |
