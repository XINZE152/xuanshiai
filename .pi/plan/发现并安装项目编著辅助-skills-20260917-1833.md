## 目标
为 PI 补充最有助于项目开发的专项 Skills，并避免安装与当前能力重复、来源不明或无法在本地使用的内容。

## 当前确认
- 当前会话已有：需求打磨、原型/视觉设计、Graphify、Git 集成审查与 `find-skills`。
- 未在用户级 `~/.pi` 下发现现成的 Skill 安装目录或安装清单；仅有全局 `AGENTS.md`。
- 全局规则已要求：中文沟通、编写新代码前先搜索并优先复用已有实现。

## 实施步骤
1. 通过已提供的 `find-skills` 能力和 PI 可识别的官方/可信注册源，检索以下高价值方向：
   - 系统化 Bug 排查与根因定位；
   - 测试设计、回归测试与浏览器端到端验证；
   - 按已安装版本检索官方文档/API 的依赖研究；
   - 可选：面向认证、权限、上传等功能的安全审查。
2. 对候选项逐一核验：维护来源、用途、所需工具、安装位置、许可证/权限说明，以及是否与现有 Skills 重复。
3. 仅选择能够由当前 PI 环境实际调用、来源可信、且不要求不必要外部凭据或高权限的 Skills；默认优先安装前三项，安全审查项仅在有可靠可用候选时加入。
4. 按 PI 的官方安装方式写入用户级 Skill 目录或注册配置；不修改当前项目业务代码、依赖或 Git 历史。
5. 重新枚举已安装 Skills，并做一次最小调用/加载验证；若某项只能安装但无法在当前运行时发现，会卸载或明确标记为不可用，不将其视为完成。
6. 交付安装清单：每项的来源、用途、安装位置、验证结果，以及未安装候选的原因。

## 验证
- 确认安装后的 Skill 能被 PI 发现并加载。
- 检查不会覆盖现有 `~/.pi/agent/AGENTS.md`。
- 检查当前项目工作区无业务文件变更。

## 风险与边界
- 只从可信来源安装，不执行来源不明脚本。
- 如官方市场需要登录、令牌、付费或用户选择版本，我会先说明阻碍，不自行提交凭据或安装替代品。
