### 关键设计决定（重要，后续复用）
1. **分店红娘完全复用总店红娘体系**：分店红娘 = 挂了 `organization_member(role_code='store_matchmaker')` 的服务红娘。故「添加红娘」直接调 `POST /admin/matchmakers` 带 `store_id`；「菜单权限」用已有的 `matchmaker_menu_permission` + `/matchmakers/{id}/permissions`，**禁止再造平行字段**（我曾误加 `organization_member.menu_permissions` 已回退）。
2. **分店分成的 key** = `commission_entry.beneficiary_type='store'` + `beneficiary_id = organization.id`（总店分成是 `beneficiary_type='service_matchmaker'`，两者靠 `beneficiary_type` 区分，不是靠 `store_id`）。`commission_entry` 仍无 `store_id` 列。
3. **金额字段一律 `Decimal`**（JSON 模式自动转字符串），不要用 `str`，否则 pydantic 直接拒收 Decimal 入参。
4. **报表口径与 `app/services/admin_home.py:dashboard` 对齐**：线上VIP = `user_membership` 有效且订单 `product_type <> 'offline_vip'`；线下VIP = `= 'offline_vip'`；线下业绩 = `payment_order.status=1 AND product_type='offline_vip'`。分店范围用 `EXISTS(resource_assignment sa WHERE sa.user_id=col AND sa.status=1 AND sa.organization_id=:store_id)`。
5. SQL 里 `DATE_FORMAT(x,'%%Y-%%m')` 必须写双 `%`（aiomysql pyformat）；`DATE_FORMAT` 的别名叫 `m` 时**不要**再用 `m` 当表别名（会歧义），`user_membership` 用 `um`。
6. **`/stores/{id}/report` 的路径顺序**：静态后缀段（`/report/summary`、`/report/monthly`）与 `/report` 段数不同，无冲突；但 `GET /meetings/options` 那类同段数冲突仍需放在动态段之前（M4 已踩坑）。

### 关键设计决定（后续复用）
1. **合伙人身份模型 = `partner_team` 一行**（owner_user_id 唯一），不建新档案表；团队名即合伙人团队名。
   团队成员 = `partner_membership(status=1)`；角色用 `user_role(role_code='partner')`。
2. **分成口径**：`commission_entry.beneficiary_type='partner'` + `beneficiary_id = 团队 owner_user_id`。
   四个 beneficiary_type 现已齐备：`service_matchmaker`(总店/分店红娘) / `store`(分店) / `promoter`(推广红娘) / `partner`(合伙人)。
3. **服务红娘不可成为合伙人**（`user_matchmaker_apply(application_type='service_matchmaker')` 存在即 409）；
   推广红娘可并存，且若其无团队则创建合伙人时自动加入自己团队（与客户端 `get_partner_center` 一致）。
4. **删除合伙人是软删除**：团队 status=2 + 成员关系全部 status=2 + `user_role` status=3（写 revoked_at）。
5. **团队变更是「记变更 + 落新关系」**：旧关系 status=3（不是 2），新关系 `ON DUPLICATE KEY UPDATE`
   兜底 `uk_partner_membership_active(promoter_id, status)`。移出才是 status=2。
6. **手工录入分成要同时写两张表**：`commission_entry`(order_id=NULL, status='AVAILABLE', source='manual') +
   `account_ledger`(account_type='user', CREDIT, AVAILABLE, source_type='commission_entry')，同事务 + 审计。
7. **`Decimal.normalize()` 会产生科学计数法**（40.0000 → `4E+1`）！展示型数字必须用
   `format(Decimal(str(v)), "f")` 再去尾零。已修 `partner_level_admin._num` 与 `promoter_level_admin._num`（M2 遗留同 bug）。
8. **TS：interface 没有隐式索引签名**，`type` 别名才有。要把查询对象传给 `adminApi` 的
   `query: Record<string, string|number|undefined>`，必须把查询类型写成 `type X = {...}` 而不是 `interface X {...}`。
9. 路由顺序：`/partners/statistics`、`/user-candidates`、`/team-options`、`/commission-entries`
   全部声明在 `/{team_id}` **之前**，否则被动态段吞掉返回 422。
