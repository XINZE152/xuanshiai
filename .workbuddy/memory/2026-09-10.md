## 线上启动崩溃：ModuleNotFoundError: No module named 'openai'

- 现象：服务器 `/home/xuanshiai` 上 uvicorn 反复崩溃重启，报 `openai` 模块缺失（traceback 显示 uvicorn 来自 `/usr/lib/python3.11/site-packages`，即系统 Python）。
- 根因：`app/services/ai/providers.py:72` 顶层硬导入 openai。导入链 `app/main.py:19` → `app/api/router.py:5` → `routes/ai_compatibility.py:39` → `services/ai/compatibility.py:52` → `ai/gateway.py:40` → `ai/providers.py:72` 属于应用启动必经路径，因此**缺 openai 会让整个 FastAPI 无法启动（不只是 AI 模块）**，与 AI 开关是否关闭无关（默认 provider 是 mock，也不影响）。
- 本地对照：`.venv` 内 openai 1.109.1，与 `uv.lock:619` 一致；`pyproject.toml:26` 已声明 `openai>=1.50,<2.0` → 属于部署环境依赖未同步，不是代码/锁文件问题。
- 修复方向：用「启动 uvicorn 的同一个解释器」重装项目依赖。`requirements.txt` 只有 `-e .`，会从 pyproject 拉全量依赖。
  - uv：`cd /home/xuanshiai && uv sync`
  - pip：`python3 -m pip install -e .`（PEP 668 报错时用 `--break-system-packages`，或改用项目 venv）
- 待确认/未实施：是否把 openai 改成惰性导入（try/except + 桩类），让非 AI 模块不被 AI SDK 缺失拖垮。
